## 0. 一页纸概览

| 项目 | 内容 |
|---|---|
| **一句话** | 你带着几个人落在一片荒地上，亲手搭起第一间棚屋、开第一块田、熬过第一个冬天——然后把它经营成一座城、一个帝国。 |
| **类型** | 殖民地建造 + 经营模拟 + 轻战略，单机为主，可暂停实时 |
| **视角** | 2D 俯视（可缩放：从单个人物 → 营地 → 城镇 → 国土） |
| **核心张力** | **资源永远不够。** 每一份木材、每一个劳力，都在逼你放弃另一件事：现在盖房还是先开田？养兵还是修渠？ |
| **单局时长** | 主线 30–60 小时；沙盒无限 |
| **目标平台** | PC（Steam）优先，键鼠 |
| **参考坐标** | RimWorld 的殖民地经营与角色故事 + Anno 的生产链 + Songs of Syx 的规模感 + 轻量贸易与战争 |
| **最大风险** | 摊子铺太大——七个纪元一路做到星海，结果每个阶段都做不深（Spore 式失败） |

**三条不可动摇的设计法则**

1. **每一块砖都看得见。** 所有建筑由玩家亲手放置、亲手决定用途；自动化只是"让居民自己按规矩干活"，任何时刻玩家都能下钻手动接管一块田、一个人。
2. **每个人都有名字。** 居民有技能、性格、关系、心情；他们会受伤、会老、会死，死了一个干了十年的老农，玩家会心疼。
3. **危机必须可归因。** 饥荒是因为你去年没存粮，被攻破是因为你城墙只修了一半，叛乱是因为你让人饿了三年。输，要输得明白。

## 1. 核心幻想与体验支柱

### 1.1 核心幻想

不是"我要征服世界"，而是——

> **"这片荒地，是我一块砖一块砖建起来的。"**

开局只有五个人、一堆木头和一片空地。玩家亲手放下第一间棚屋、开出第一块田、挖出第一口井。第一个冬天冻死了一个人，第二年他学会了先盖房再开田。十年后他站在城头往下看，看到的是自己亲手规划出来的秩序：田连着渠，渠通着仓，仓挨着工坊，城墙刚好把这一切围在里面。

成就感来自三件具体的事：

- **看得见的成长**：从草棚到石城，每一栋建筑的位置都是自己定的，地图上能一眼看出"这是我建的"。
- **每个人的故事**：最早那个种田的老农、那次袭击里活下来的猎人、第一个出生的孩子——人口不是数字，是一群有名字的人。
- **系统为我所用**：分工、贸易、自动化是玩家主动解锁的**工具**，用来把摊子铺得更大，而不是用来替玩家玩游戏。

**玩家扮演的是经营者**：种什么、建什么、谁去干什么、跟谁做生意、什么时候打仗。所有决定都落在地图上，看得见后果。

### 1.1.1 三层四维：本作的核心竞争力

绝大多数殖民地经营游戏只做其中一层。本作做四维，而且**四维共用同一批状态**：

| 层 | 维度 | 玩家看到什么 | 提供什么 | 只有这一维会怎样 |
|---|---|---|---|---|
| **宏观** | 聚落 | 产量、价格、税收、人口结构 | **压力**——每个决定都有代价 | 变成 Excel，赢了没情绪（希克斯之歌） |
| **中观** | **家族**（利益） | 5–8 个家族、经营权、家族民意、请愿 | **政治传导**——不满变成具体的人来找你谈 | 民意退回抽象仪表盘，没人对政策有反应 |
| **中观** | **族群**（认同） | 4–6 个族群、同化度、关系 | **摩擦**——同样的政策对不同人群效果不同 | 变成抽象派系，没有质感（维多利亚 3） |
| **微观** | 关键人物 | 5–20 人的能力、忠诚、生死 | **记忆**——数字背后有具体的人 | 变成小说，管不动生产（矮人堡垒） |

**家族与族群正交**：家族回答"这产业谁在经营、谁在向你提意见"，族群回答"这些人信什么、跟谁一伙"。
两者交叉，才出现真实历史里最典型的矛盾——**某个族群被某个家族长期把持某行业**。

**玩家是总统**：可以任命、罢免、批地、立法、批请愿，但不能直接指挥家族怎么经营。
民意由家族汇总并转达，家族民意太低会下台，太高会坐大。

**一条完整的四维链**（本作的设计样板）：

```
粮价从 1.0 涨到 1.6                          【宏观】
→ 农业家族利润率翻倍，申请扩大经营权            【家族】
→ 总统批地，新田占了少数族群聚居区边缘           【族群】
→ 该族群家族提"给块地"请愿，总统拒绝            【家族】
→ 家族民意 38→28，家主忠诚 70→52              【人物】
→ 他消极经营，辖区 8 栋建筑效率 ×0.82           【宏观】
→ 连续两年民意 < 30，家主下台，另一家族接盘      【家族】
→ 新家族属主体族群，族群关系 −8                 【族群】
```

**这条链没有一环是脚本写死的**，全部由状态传导产生。这就是"能看见人的经济模拟"。

> 详细设计见分册 [07 家族、族群与人物](07_人物与族群.md)。

### 1.2 四条体验支柱

| 支柱 | 含义 | 反例（要避免的） |
|---|---|---|
| **亲手经营** | 建筑、布局、分工全部由玩家决定；自动化是加速器，不是替代品 | 后期变成看数字上涨，玩家没事可做 |
| **人的重量** | 家族有名有姓、有世代、会下台；关键人物有履历、有忠诚、会死；族群有语言、习俗、信仰，会摩擦也会融合 | 人口只是一个会涨的数字；家族与族群只是换皮 |
| **危机即节奏** | 饥荒、瘟疫、袭击打断平静，逼玩家在资源之间做取舍 | 危机是随机天罚，与玩家经营无关 |
| **规模即成就** | 从 5 人到 500 人、从木棚到石城，成长必须肉眼可见 | 换个阶段就换一套规则，前面的积累作废 |

### 1.3 情感曲线设计

```
好奇（这地方能活吗？）
  → 手忙脚乱（搭棚、找食、熬冬）
  → 第一次撑过冬天（"我活下来了"）
  → 扩张（开田、建工坊、招人）
  → 第一次危机（饥荒 / 袭击，差点全崩）
  → 稳住（有存粮、有城墙、有商路）
  → 繁荣（人口上百，城镇成形）
  → 野心（对外通商、结盟、开战）
  → 帝国的重量（疆域太大，一个决定牵动全局）
```

**关键节点是"第一次撑过冬天"。** 那一刻玩家第一次感到"我建的东西能活下来"——这是整个游戏成就感的种子，必须做扎实：要让玩家记得自己是怎么熬过来的（先盖房还是先开田、要不要杀最后一只牲畜）。

**后期不做"失去掌控"的戏码。** 疆域变大带来的应该是"更复杂的经营"，而不是"被迫把地盘交出去"。玩家永远可以选择亲自管理某座城——只是时间成本会告诉他该收手了，而不是系统强行剥夺。

## 2. 参考游戏拆解：学什么，不学什么

| 参考作品 | 学什么 | 明确不学什么 |
|---|---|---|
| **Stellaris（群星）** | 尺度跃迁的仪式感；科技抽卡带来的叙事性；中期危机（Mid-game Crisis）作为节奏阀门；飞升作为"非军事胜利"。 | 后期舰队微操疲劳；大量同质化星球管理；外交 AI 过于可预测。 |
| **Factorio** | 物流即玩法；瓶颈驱动玩家思考；"蓝图"让重复劳动变成设计劳动；稳定运行的产线本身就有美感。 | 纯工程沙盒没有社会层，缺少"人"的冲突。 |
| **Victoria 3** | POP 与阶层；法律/制度作为"慢变量"改变社会；激进派与合法性构成内部压力。 | 经济模型过于黑箱，玩家看不懂因果；上手门槛过高。 |
| **RimWorld**（核心参考） | 殖民地经营的完整闭环（吃住穿医娱）；有名有姓的居民与他们的关系、伤病、死亡；事件驱动而非数值驱动；"工作优先级"式可控自动化——玩家定规矩，居民照做，随时可手动接管。 | 单张地图、没有规模成长；后期内容靠模组堆。 |
| **Anno 1800** | 多阶层人口的需求链；生产链的可视化；港口贸易的节奏感。 | 岛屿地图太小，战争存在感弱。 |
| **Civilization VI** | 区域（District）布局的空间决策；相邻加成带来的"选址有讲究"。 | 一局内时代跨度太短，缺乏成长纵深。 |
| **Total War** | 战略层 + 战术层的双轨；自动战斗作为可选。 | 战术战斗成本极高，内容量爆炸。 |
| **Songs of Syx** | 超大规模人口（万人级）的群体模拟；简陋画面下的深度；"工作优先级 + 房间建造"的可控自动化。 | 表现力不足；一万人全是数字，记不住任何一个人；价格模型是简化供需。 |
| **Dwarf Fortress（矮人堡垒）** | 极致的个体深度：每个矮人都有历史、性格、关系、伤势；故事从系统里长出来而不是写出来。 | 学习曲线近乎垂直；七个矮人管不动一个帝国；大量内容玩家永远看不到。 |
| **Distant Worlds（远行星号）** | "一切可交给 AI 代管"的自动化层级；帝国规模的真实感。 | 玩家容易变成旁观者；经济与社会是黑箱，看不出因果。 |
| **秩序：新曙光** | 拟真星球环境（公转、转轴倾角、二十余种天气）；房间级动线布局。 | **反面教材**：功能列表极长但每一样都不深，Steam 好评率仅 57%，玩家评价集中在"内容很多但很空"。 |
| **Humankind** | 时代跃迁时"换文明"的机制，让每局不同。 | 每换一次就丢掉前面的积累，玩家情感断裂。 |
| **Oxygen Not Included** | 规则化自动化的深度（传感器 + 逻辑门）；殖民地生存压力。 | 学习曲线陡峭，前期劝退。 |
| **Terra Invicta** | 从地球到太空的连续尺度；同一批组织跨阶段延续。 | 界面信息密度过高。 |
| **Spore** | （反面教材）五个阶段各自独立，互不继承，最终没有一个做深。 | **绝对不做的模式。** |

### 2.1 从拆解中提炼的三条结构性判断

**判断一：尺度跨越必须是"同一系统的放大"，不能是"换一个游戏"。**
Spore 失败的根本原因是每个阶段都重写了规则。本作的做法是：**永远只有一套"资源—生产—人口—治理"模型**，纪元变化只改变参数量级和新增一层抽象，不改变底层语法。

**判断二：自动化是"减负"，不是"替代玩家"。**
Factorio 的摩擦来自空间与物流，本作的摩擦来自**资源稀缺与危机**——不是"下属不听话"。自动化（工作优先级、模板复制、商队自动跑线）的意义是让玩家管得动更大的摊子，但任何一块田、一个人，玩家点进去都能手动改。**一旦玩家发现自己无事可做，游戏就死了。**

**判断三：危机必须可归因。**
每一次崩盘都要能追溯到玩家的某个具体决定：没存粮、城墙没修完、扩张太快、把唯一会治伤的人派去打仗。玩家输了要能说出"我错在哪"，而不是"这游戏随机搞我"。这是"经营成就感"的底线——**赢要赢得明白，输也要输得明白。**

### 2.2 竞品定位：我们和它们差在哪

四款最接近的作品，各自强在不同的尺度上：

| 维度 | 远行星号 | 秩序：新曙光 | 希克斯之歌 | 矮人堡垒 | **本作** |
|---|---|---|---|---|---|
| 规模 | 舰队 / 帝国 | 殖民地（百人） | **万人** | 七到两百人 | 万人 |
| 建造手感 | 简化 | 房间级动线 | 建筑级 | 房间级 | **格子级，亲手放** |
| 个体叙事 | 无 | 雇员有背景 | 无 | **极深** | 关键人物 + 大众统计 |
| 文化 / 族群 | 有种族 | 无 | 有种族 | 有种族 | **文化族群层（本作独有）** |
| 经济深度 | 贸易价格 | 资源管理 | 简化供需 | 几乎无 | **保留价 + 劳动力定价 + 人口市场** |
| 自动化 | 可全托管 | 无 | 工作优先级 | 工作优先级 | 规则 + 涌现 |
| 时间跨度 | 沙盒 | 单星球 | 单一时代 | 世代 | 七纪元（首版前四） |
| 上手难度 | 中 | 中 | 中 | 极高 | 中（不做硬核） |
| 核心乐趣 | 跑商 + 战斗 | 建造 + 生存 | 规模调度 | 故事涌现 | **经营因果 + 人的重量** |

**三条护城河**（别人抄不走，因为要动底层架构）：

| # | 护城河 | 为什么难抄 |
|---|---|---|
| 1 | **三层叙事**：宏观压力 → 族群摩擦 → 人物命运 | 需要经济、社会、人物三套系统共用同一批状态，后加的团队通常只做其中一层 |
| 2 | **经济因果链**：粮价 → 工资 → 迁移 → 族群结构 → 产能 | 需要"劳动力也是商品"的定价模型，多数游戏工资是写死的 |
| 3 | **延迟因果**：今年的决定，三五年后才显形 | 需要完整的状态持久化与可追溯记录，快餐化产品不会做 |

> **一句话定位**：不是"小号希克斯之歌"，也不是"简化矮人堡垒"，而是**"能看见人的经济模拟"**。

### 2.3 砍功能的判断标准

秩序：新曙光功能列表极长，Steam 好评率仅 57%，评价集中在"内容很多但很空"。这是本作最大的前车之鉴。

**每加一个功能，只问一句**：

> 它让**因果链更深**，还是只是让**列表更长**？

| 加深因果（做） | 只是变长（砍或延后） |
|---|---|
| 岗位购买、维护费、工资随价格浮动 | 数百项科技（先做 20–30 项，每项改一条链） |
| 族群同化、关系矩阵 | 独立小游戏式的战术战斗 |
| 关键人物的忠诚与继承 | 多种族玩法（物种层延后到事件解锁） |
| 季节对农业与储备的影响 | 每颗星球一套独立季节规则 |
| 价格延迟传导 | 舰船改装、装备词条 |

**首版范围收口**：拓荒 + 定居 + 城邦三个纪元，单张地图，人类一个物种、4–6 个文化族群，20–30 项科技。

## 3. 玩家的时间线：七个纪元

> 设计原则：纪元不是"关卡"，而是**同一局游戏的不同密度**。跃迁不重置存档，只改变可操作范围和抽象层级。

| # | 纪元 | 空间尺度 | 人口量级 | 决策粒度 | 玩家身份 | 新增自动化层 | 核心新问题 |
|---|---|---|---|---|---|---|---|
| 1 | **拓荒** | 一个营地 | 5–30 | 按天 | 幸存者之一 | L0 手动 | 会不会饿死 |
| 2 | **定居** | 一个村镇 | 30–300 | 按旬 | 村长 | L1 模板 | 分工与储存 |
| 3 | **城邦** | 城市 + 周边 | 300–5,000 | 按月 | 执政官 | L2 规则 | 贸易与阶级 |
| 4 | **国家** | 数座城市 | 5 千–50 万 | 按季 | 君主 / 议会 | L3 管理者 | 税收与常备军 |
| 5 | **帝国** | 一片大陆 | 50 万–5,000 万 | 按年 | 皇帝 / 内阁 | L4 制度 | 多民族与殖民 |
| 6 | **行星** | 全球 | 亿级 | 按多年 | 全球领袖 | L5 自治 | 生态与总动员 |
| 7 | **星海** | 多星系 | 万亿 | 按代 | 文明意志 | L5+ | 他者与意义 |

**关于时间**：底层时钟始终是 **1 tick = 1 秒，60 tick = 1 年**（贸易每 5 tick 结算一次，见 §4.9.1）。纪元改变的只是**玩家关注什么粒度的事**——拓荒期每秒都在操心今天吃什么，帝国期则在按年规划版图。时钟本身不变。

**核心体验在前四个纪元（拓荒 → 国家）**：从 5 个人到 5 万人的经营成就感，这是游戏的主体。第五纪元"帝国"是长线目标。**行星与星海是远期愿景，不在首版范围**——先把"把一片荒地经营成一座城"做扎实，再谈更大的尺度。

### 3.1 纪元跃迁的规则

跃迁不是"攒够科技点自动升级"，而是**三重条件同时满足**：

1. **技术门槛**：掌握该纪元的关键技术（如蒸汽机、轨道运载、聚变）。
2. **结构门槛**：治理容量、粮食盈余、行政建筑达到阈值。
3. **叙事门槛**：完成一次"跃迁事件"——一个不可跳过的多选决策（例如：是否用旧制度镇压新阶层）。

**跃迁的代价**：旧制度会部分失效。玩家在跃迁后的 10–20 个 tick 内处于"制度真空"，效率下降、抵抗上升。这段时间是游戏节奏的高潮，也是最容易崩盘的时刻。

> **设计意图**：让"升级"变成"危机"，而不是"奖励"。这是与 Civ 系列最大的区别——时代不是免费的加成，是一次结构性的地震。

### 3.2 时间的分层

- **战略层**：可暂停，1x / 2x / 4x / 8x。所有指令在此下达。
- **战术层**：进入战斗或"下钻"时，时间自动降到 1x 并可暂停，微观单位可见。
- **模拟层**：后台 tick，玩家不可见，但可回放（"过去 30 天这个村庄发生了什么"）。

**关键设定**：玩家可以在任意时刻按下"下钻"，把镜头拉到一个具体的小人身上，接管他的行动。此时上层时间减速到 0.1x。**这个功能从第一分钟就存在，永不取消。** 它是"尺度感"和"情感锚点"的来源。

## 4. 核心系统

### 4.0 四板块总览与耦合

全部玩法归为四块，**没有一块可以独立操作**——动一块，另外三块必然跟着变。

| 板块 | 玩家决定什么 | 产生什么 | 消耗什么 |
|---|---|---|---|
| **① 建筑与科技** | 建什么、建在哪、升到几级、研究什么 | 产能、岗位、解锁 | 木材/铁/煤、金币、土地 |
| **② 人力** | 谁去干什么、干多少、招不招人 | 产出、税收、兵源 | 口粮、工资、住房 |
| **③ 法律与制度** | 税率、人口政策、政体 | 财政收入、人口增速、经营容量 | 民怨、声望 |
| **④ 对外政策** | 跟谁贸易、跟谁开战、怎么统治 | 金币、资源、土地、人口 | 兵力、后勤、外交信誉 |

**六条咬合规则（整个游戏的骨架）**

1. **建筑产生产能与岗位**：没有建筑就没有岗位；没有岗位，人就无处可去。
2. **人力决定产出与税收**：就业人口 × 效率 = 产出；产出 × 税率 = 财政收入。
3. **法律调节人力与财政**：税率高 → 钱多但民怨涨；人口政策松 → 人来得快但口粮紧。
4. **建筑产能决定贸易上限**：能出口多少，取决于年产多少（见 §4.9）。
5. **战争消耗人力与产能**：征兵抽走劳力，军工转产压低民用产出（见 §4.5）。
6. **贸易反哺建筑与人力**：进口材料绕过本地资源瓶颈；卖粮换钱买工具。

**一张图**

```
        ┌───────────────┐
        │ ① 建筑与科技  │──产能 / 岗位──┐
        └───────────────┘              ↓
               ↑                  ┌───────────┐
       解锁 / 装备 │               │ ② 人力    │──产出──┐
               │                  └───────────┘        ↓
        ┌───────────────┐              ↑         ┌───────────┐
        │ ④ 对外政策    │←──兵源───────┘         │ ③ 法律    │
        └───────────────┘                        └───────────┘
               ↑                                       │
               └──────────── 金币 / 资源 ←─────────────┘
```

|---|---|
| ① 建筑与科技 | §4.1 建筑与生产链、§4.2 自动化阶梯、§4.6 科技 |

#### 4.0.1 架构原则：只给规则，不给结果

**这是整个模拟层的底线，也是本作与"数值驱动"游戏的根本区别。**

每个 AI 国家不是一张配置表，而是一个**会自己运转的小社会**：

```
输入：初始资源、地形、几条决策规则
过程：每年按规则生产、建设、生育、教育、通商、收税
输出：人口结构、等级构成、贫富强弱、贸易倾向——全部是涌现的
```

**禁止三件事**：

1. **禁止写死宏观数值**——不许出现"这个国家三级公民占 12%"这种直接设定。它必须是"教育投入 × 培养年限"算出来的。
2. **禁止全局最优**——AI 看不到全球市场全貌，只能用自己知道的局部信息做决策；它会犯蠢，会反应迟钝，这才真实。
3. **禁止预知未来**——AI 不知道明年会不会打仗，只能按当下状况调整。

**涌现出来的东西**（不写，但会出现）：

| 现象 | 从哪来 |
|---|---|
| 各国人口年龄结构 | 出生率 × 死亡率 × 历史累积 |
| 各国等级构成 | 学堂数量 ÷ 适龄人口 → 升级概率 |
| 全球流动人口的结构 | 各国迁出量的加权 |
| 人口市场的价格 | 各国出价的竞价结果 |
| 谁强谁弱 | 资源禀赋 × 政策选择 × 偶然事件 |
| 战争与结盟 | 实力对比 × 资源争夺 × 关系演变 |

> 玩家的乐趣不是"读懂一张表"，而是"看着五个国家各自走出一条不同的路，然后判断谁能合作、谁该打"。

### 4.10 危机与节奏

#### 4.10.1 三类危机

| 类型 | 触发 | 作用 | 示例 |
|---|---|---|---|
| **跃迁危机** | 每次纪元跃迁 | 强制玩家重构制度 | "旧法律不再适用于蒸汽时代，你要镇压还是妥协？" |
| **内部危机** | 民怨到顶 或 经营漏风持续 | 制造存在性威胁 | 行省独立、军队哗变、宗教分裂、继承人战争 |
| **外部危机** | 时间轴固定（每纪元中段） | 打破平衡，制造"共同敌人" | 更先进的文明抵达、天灾、瘟疫、外星信号 |

#### 4.10.2 节奏阀门：重大危机

**每 25–35 分钟现实时间**，游戏强制暂停，弹出一个**危机事件**：

- 类型：大规模袭击、瘟疫爆发、粮荒、商队求购、邻国勒索；
- 3 个应对选项，每个都有明确代价（打 / 撤 / 谈 / 花钱消灾）；
- 不可自动化、不可跳过——这是"老板拍板"的时刻；
- 选项没有最优解，只有不同的代价。

**作用**：
1. 后期"挂机感"的解药；
2. 逼玩家在资源之间做取舍；
3. 让每一局的故事不一样（"那年瘟疫，我选择了封城"）。

> 危机应该**从玩家的经营状况里长出来**：粮仓空 → 更容易闹饥荒；城墙没修完 → 袭击损失更大。不是随机天罚。

## 5. 核心循环（三层嵌套）

```
┌─────────────────────────────────────────────────────────┐
│  纪元循环（40–80 小时一局）                              │
│  拓荒 → 定居 → 城邦 → 国家 → 帝国 → 行星 → 星海          │
│  每次跃迁 = 一次结构性危机 + 一层新自动化                  │
└─────────────────────────────────────────────────────────┘
              ↓ 内含
┌─────────────────────────────────────────────────────────┐
│  战略循环（每 30–60 分钟）                                │
│  看瓶颈 → 建建筑 / 定规则 / 雇管理者 → 扩张或巩固 → 处理危机│
│  → 摊子大了管不过来 → 雇人、建制度、修路 → 再看瓶颈         │
└─────────────────────────────────────────────────────────┘
              ↓ 内含
┌─────────────────────────────────────────────────────────┐
│  操作循环（每 1–5 分钟）                                  │
│  建一座建筑 → 连一条物流 → 调一次配额 → 看数字变化         │
│  → 触发一次工艺突破 → 微小的正反馈                        │
└─────────────────────────────────────────────────────────┘
```

**循环的健康标准**：玩家在任意时刻，都应该同时有**一件想做的事**（短期）和**一件担心的事**（长期）。如果只有前者，游戏变成清单；如果只有后者，游戏变成焦虑。

## 6. 失败、胜利与重开

### 6.1 失败条件（四种，都不是"被打死"）

| 失败类型 | 触发 | 表现 |
|---|---|---|
| **民怨崩盘** | 长期粮荒 / 欠薪 / 缺员 → 积怨到顶 | 居民大规模离走、暴动，聚落瓦解 |
| **人口崩溃** | 核心聚落人口 < 阈值 | 退回拓荒状态，几乎从零开始 |
| **生态崩溃** | 行星环境值 = 0 | 土地不可居住，强制迁移或灭亡 |
| **被吞并** | 被更强的势力征服 | 游戏结束，但保留"遗产"（部分科技/建筑图纸） |

### 6.2 黑暗时代：软重启机制

失败不等于读档。触发失败后，游戏进入**黑暗时代**：

- 玩家从残存的 1–3 个聚落重新开始；
- **继承部分科技**（已完成的工艺突破不会消失）；
- **继承世界状态**（你曾经的帝国变成废墟，上面有新的势力）；
- 目标：在 100 tick 内把民怨压下去、把人口补回来，否则真正结束。

> **设计意图**：解决 4X 游戏"崩盘即弃档"的问题。失败变成一个**新的开局**，而不是终点。这也让"帝国兴衰"这个主题在机制上成立。

### 6.3 胜利条件（四条，都不是"消灭所有人"）

| 胜利 | 条件 | 主题 |
|---|---|---|
| **统一** | 把所有已知势力纳入同一行政体系（武力/外交/附庸皆可） | 秩序 |
| **飞升** | 完成跨纪元巨型工程（例如"把整个文明上传"） | 超越 |
| **长存** | 连续存活 N 个纪元且民怨从未崩盘 | 韧性 |
| **离去** | 建造世代方舟，放弃母星，前往未知 | 牺牲 |

**没有"分数胜利"。** 四条路线代表四种价值观，玩家在游戏过程中会逐渐发现自己走向哪一条。

## 7. UI 与信息设计原则

这是本作能否被大众接受的关键。**系统再深，看不懂就是失败。**

### 7.1 四级缩放

| 层级 | 视野 | 可见元素 | 主要操作 |
|---|---|---|---|
| **个体** | 1 个屏幕 20 人 | 具体的人、动作、情绪气泡 | 直接指挥 |
| **聚落** | 1 个村镇 | 建筑、道路、物流流向 | 建造、配额 |
| **区域** | 一片领土 | 聚落节点、资源、边界 | 规则、代理任命 |
| **战略** | 大陆/星球/星系 | 势力色块、航线、战力 | 外交、战争、立法 |

缩放是**连续**的，不是切换场景。滚轮从一个人拉到星系，中间没有加载。

### 7.2 三条信息设计铁律

1. **任何数字都必须能"点开看因果"。** 点"木材 −20"，弹出："砍伐 35，运输损耗 5，被隔壁村买走 40，库存 10"。
2. **任何自动化都必须"可见"。** L2 规则在地图上显示为流动的箭头，L3 代理显示为一个小人站在建筑旁，鼠标悬停显示"他现在在想什么"。
3. **任何危机都必须"提前预警"。** 抵抗值到 60 时，地图上出现小图标；到 80 时，出现具体的人名和诉求。**永远不要用突然的弹窗惩罚玩家。**

### 7.3 后期减负：仪表盘

玩家在帝国纪元后，主要界面从"地图"变为"仪表盘"：

- 左：**瓶颈列表**（系统自动检测"哪条链在拖后腿"，按严重度排序）；
- 中：**地图**；
- 右：**待决事项**（危机事件、外交、待办）。

玩家 80% 的时间应该花在"读瓶颈"和"做决策"，而不是"找问题"。

## 8. 开发方案

### 8.1 技术基座（只谈结构决策，不涉及实现）

> 依据你现有技术栈（Unity + TopDownEngine + Mirror + Pure MVC + MoreMountains/Feel），以下为架构层判断。

| 决策 | 选择 | 理由 |
|---|---|---|
| **引擎** | Unity（复用现有经验与插件生态） | 2D 工具链成熟，Feel 可直接用于反馈层 |
| **模拟与表现分离** | **必须**。模拟层是纯数据 tick，表现层只读取快照 | 后期万人级人口时，表现层不能逐个体渲染 |
| **时间系统** | 分层 tick（战略 tick / 战术 tick / 模拟 tick），三者可独立变速 | 支持"下钻减速"而不影响全局 |
| **数值类型** | 定点数（避免浮点累积误差导致存档漂移） | 长局（80 小时）必然遇到 |
| **存档** | 全量快照 + 增量日志（支持回放与黑暗时代继承） | "过去 30 天发生了什么"需要日志 |
| **多人** | **首版不做**。Mirror 保留在架构里但不启用 | 大战略 + 自动化联机的同步成本极高 |
| **Mod 支持** | 数据驱动（所有建筑/科技/事件用外部配置），首版即留接口 | 这类游戏的生命周期靠社区 |

**性能红线**：目标在 5 万人口、300 聚落、2000 建筑时，模拟 tick 耗时不超 4ms（单核）。这是能否做到"行星纪元"的前提。若达不到，行星纪元降级为"抽象层"。

### 8.5 规模与资源评估（必须诚实面对）

**这个项目的完整版，是一个 5–7 年、8–15 人团队的量级。** 具体拆解：

| 职能 | 完整版所需 | 最小可行（M-A 切片） |
|---|---|---|
| 程序（模拟/系统） | 2–3 人 | 1 人（你） |
| 程序（UI/工具） | 1–2 人 | 0.5 人 |
| 系统策划 | 1–2 人 | 1 人（你） |
| 内容/叙事 | 1–2 人 | 0（用程序生成 + 模板） |
| 2D 美术 | 2–3 人 | 1 人（可外包/素材） |
| UI/UX | 1 人 | 0.5 人（可外包） |
| 音频 | 0.5–1 人 | 0（采购） |
| **合计** | **8–15 人 / 5–7 年** | **2–3 人 / 12–18 个月** |

**三条降本策略**：

1. **美术走"低帧数像素 + 强光照"路线**（复用你已有的 2.5D Cel Shading + 描边方案），单帧角色 + 程序化动画，把美术成本压到最低。
2. **内容走"程序生成 + 模板 + 参数化事件"**，叙事靠系统涌现而非手写剧本。这符合"禁止固定专名"的要求，也大幅降低内容量。
3. **砍掉战术层的手工战斗**。首版只做"战略层结算 + 1 个可选的战术演示关"，把资源集中在系统深度上。

## 9. MVP 切片建议（如果只做一件事）

**做 M-A：5 个人 → 300 个人，60–90 分钟。**

包含：
- 拓荒 → 定居 → 城邦的前两个半纪元；
- L0 手动 / L1 模板 / L2 规则 三层自动化；
- 一次"摊子太大"的节点：玩家决定雇第一个管理者；
- 一场 20 人的小规模战斗（可用 L0 微操）；
- 一条会触发"工艺突破"的完整生产链（木材 → 木板 → 工具）。

**这个切片能验证三件事**：
1. 从手忙脚乱到"雇人替我管事"，成就感是否成立；
2. 规则编辑器是否易懂（这是最大的 UX 风险）；
3. 村庄尺度是否足够有趣（如果不好玩，扩到帝国也不会好玩）。

**切片失败的最可能原因**：规则编辑器太复杂。备选方案是把它做成"填空式"而非"编程式"——玩家从预设模板里选，只改数字。

## 10. 待决策清单

以下几个问题会显著影响后续所有设计，建议在动工前定下来：

| # | 问题 | 选项 A | 选项 B | 倾向 |
|---|---|---|---|---|
| Q1 | 世界是**程序生成**还是**手工地图** | 程序生成（重玩性高） | 手工（叙事强） | 程序生成 + 手工地标 |
| Q2 | 是否保留**战术层微操** | 保留（情感强） | 砍掉（省成本） | 保留但仅限"下钻"时 |
| Q3 | **殖民对象**是人形种族还是非人 | 人形（代入强） | 非人（避免道德争议） | 人形；物种层（精灵/哥布林）后期事件解锁，**文化族群层开局即有** |
| Q4 | 单局是否有**明确终点** | 有（四条胜利） | 无（无限沙盒） | 有，但可继续玩 |
| Q5 | **黑暗时代**是否继承科技 | 继承（鼓励重开） | 不继承（惩罚更重） | 继承 |
| Q6 | 首发是否支持 **Mod** | 支持 | 不支持 | 支持（数据驱动天然支持） |
| Q7 | 是否做**多人** | 做 | 不做 | 首版不做 |
| Q8 | **时间轴**是否统一为 1 秒/tick、60 tick/年、贸易 5 tick 一次 | 统一（需重构主循环） | 贸易独立运行 | 原型阶段先独立，验证后再统一 |
| Q9 | 是否允许玩家**逼仓**（大资金扫货推价再反手卖） | 允许（真实、有趣） | 单 tick 报量硬上限 | 允许但有上限 |
| Q10 | **学识**是否可交易 | 不可交易（保持非商品） | 天价可交易 | 不可交易 |

## 附录 A：一局游戏的典型 90 分钟（用于验证节奏）

| 时间 | 玩家在做什么 | 系统在教什么 |
|---|---|---|
| 0–10 min | 5 个人找食物、搭棚子，冻死 1 个 | 资源是有限的，人会死 |
| 10–25 min | 建第一个伐木营、第一块田，人口到 20 | 生产链的概念 |
| 25–40 min | 食物不够，手动调度太累，第一次用"模板"复制农田 | L1：重复劳动可以复制 |
| 40–55 min | 木材总是运不到工地，学会设置"木材 < 50 就调运" | L2：规则比手速可靠 |
| 55–70 min | 人口到 120，出现第二个聚落，管不过来了 | 经营容量的存在 |
| 70–85 min | 雇了第一个管理者，给他预算和目标 | L3：花钱买时间 |
| 85–90 min | 管理者效率只有预期的 70%，但他自己修了条路 | 人是变量，随时可接管 |

**如果这 90 分钟好玩，整个游戏就成立。如果不好玩，做到星海也不会好玩。**
