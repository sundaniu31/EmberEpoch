## 设计文档

当前统一设计基准为 **v1.31（2026-10-23）**。从[主方案](殖民扩张自动化文明模拟_初步开发与设计方案_v0.1.md)开始，再按需要阅读专题。主方案保留原文件名；旧版本修订和重复过程记录已合并，详细规则各有唯一维护位置。

| 专题 | 内容 |
|---|---|
| [人物与社会](设计文档/人物与社会.md) | 能力岗位、关系记忆、诉求、信息调查、对话承诺、招募培养与 UI |
| [人口与聚落](设计文档/人口与聚落.md) | 时间、人口劳力、住房、库存运输、粮食消费、缺粮恢复与用途顺序 |
| [产业与建设](设计文档/产业与建设.md) | 行业、建设用工、整数供给格、配方升级、产业连线与 UI |
| [贸易与财政](设计文档/贸易与财政.md) | 国家贸易、动态储备与价格、成交运输付款、四类费用与 UI |
| [军事与占领](设计文档/军事与占领.md) | 军团命令与状态机、兵种装备、占领、战损维修和 UI |
| [技术与美术](设计文档/技术与美术.md) | 团结引擎基准、CPU/GPU 分工、逐弹碰撞、性能与像素素材规范 |

| [待审设计](设计文档/待审设计.md) | 未定参数、科技治理、迁移生命周期、气候扩张与后续讨论 |

UI 制作说明分别位于：人物第十二节、人口第8节、产业第7节、贸易第5节及财政第9节、军事第8节；技术与美术负责渲染和素材规范。

本轮确认粮食同一时点的处理顺序：**符合现有规则的新出口成交锁货→居民本次消费→仓储加工线按建立先后取粮**。未成交单不锁货，既有锁货/在途/工厂暂存不挪用，连线顺序读取存档后不改变。详细规则及 UI 见[人口与聚落第7、8节](设计文档/人口与聚落.md)。单线余粮不足配置量时如何交付仍待审核。

## 原型与代码状态

仓库的 [index.html](https://github.com/sundaniu31/EmberEpoch/blob/main/index.html) 是早期单文件网页原型；[simulation](https://github.com/sundaniu31/EmberEpoch/tree/main/simulation) 保留旧市场模型、说明和测试脚本。可直接在浏览器打开相应 HTML。

这些实现包含旧时间、人口、建筑或市场规则，与当前设计并不完全一致。本次只整理设计文档，未修改原型、模拟脚本或实际团结工程，也未运行新的游戏模型、性能测试或制作 UI。整体设计完成后再推进实现与验证。

本地 Version1 下的 Demo、截图、参考图和两份既有备份保留；备份不提交到 GitHub。被删除的远端旧分册可从 Git 提交历史查看，不再作为当前规则入口。

## 后续

先确认仓储单线不足额交付规则，再逐项完善[待审设计](设计文档/待审设计.md)。继续采用“先提问→提交方案→用户批准→写入文档”的方式，不把参考表、旧原型或待审方向自动视为生效规则。
