# 产业与建设

> v1.31 · 2026-10-23。本文是产业、建设和产业 UI 的现行设计入口；记录已批准规则，不表示游戏、UI 或模型已实现。具体平衡数字集中于[参考数值与事件](参考数值与事件.md)，未决问题集中于[待审设计](待审设计.md)。

## 1. 产业结构与决定权

六个经济行业保持为农业、矿业、工业、商业、军事、学术；总统府属于行政与公共仓储体系，不是第七个行业。行业内部可以增加建筑层次、配方与等级，不依行业数量扩张。

| 行业 | 主要作用 | 既有建筑参考 |
|---|---|---|
| 农业 | 生产粮食，支持实际生活供给 | 农场／农庄 |
| 矿业 | 提供石、铁、煤及能源原料 | 矿洞／矿场 |
| 工业 | 将原料加工成半成品、工具、建材与装备 | 铸铁厂及通用加工设施 |
| 商业 | 贸易、财政管理与结算服务 | 银行，具体服务另审；不直接产钱 |
| 军事 | 征募、编组与驻兵 | 兵营，不生产库存资源，不设部队训练 |
| 学术 | 工艺知识、研究与传播 | 大学，具体数值另审 |

表中名称是既有内容参考，不等于已批准完整建筑清单或开局编制。林业、教育、宗教、情报、外交、科研等属于十一类人事职责，与六行业不是同一分类，详见[人物与社会](人物与社会.md)。

玩家决定选址、建造、升级、配方、启停、用工目标与上限、行业优先级、预算、供给线和任免。领导人的能力与处境影响执行结果，可汇报、提出请求或建议；不代替玩家改配方、调人、分配产能或取得建筑经营权。亲属背景不构成家族对行业的所有权。

产业之间保留五类联系：农业提供生活粮食；工业工具可以改善其他生产；能源支持相应高级设施运行；物流限制跨聚落调运时间与容量；军事改变实际控制与资源接触条件。具体能源、工具和高级设施配方仍须审核，不据此增加自动消耗项目。

## 2. 建设、用工与技术

### 2.1 建造流程

1. 玩家选择已控制且道路连通的地块，并查看建筑条件。
2. 使用建筑所在聚落的实际可用材料；外地和在途材料须先运抵。
3. 施工临时占用本聚落可用劳动力，与生产、其他施工和军事不得重复占人。进度按游戏时间运行，缺粮等劳动效率影响作用于实际进度。
4. 完工先释放施工占人，再依玩家确认的用工目标从当地待业劳动力补员；不足时保留空岗，不把完工写成自动满员。

施工材料、施工报酬和专项支付分别记账，材料不再按市价重复收费，见[贸易与财政](贸易与财政.md)。造价、工期、施工人数、施工取消及自愿拆除的返还方式仍待审；旧稿“无退款”和远端旧稿“返还一半”不能同时作为规则。建筑可由玩家决定拆除，实际解除的人手不自动填到其他建筑。

### 2.2 用工目标和自动补员

总人口、可劳动人口、待业劳动力分别统计，详见[人口与聚落](人口与聚落.md)。待业池只包含当前可劳动且未被其他工作占用的人；儿童、不可劳动者及已占用人手不在可招用余量内。

默认用工目标与默认上限采用建筑设计岗数，玩家可以调整上限、启停和经营安排，也可保存用工模板。默认补员只是执行玩家目标，从待业池补足；玩家可暂停、撤销或修改。跨建筑抽人必须由玩家决定或明确授权。领导的建议可先形成用工方案，供玩家批准、拒绝或修改。

保留用工上限拖动与下一人的边际增益显示。它与税法等粗档位政策分别设计，不把所有政策改为连续滑杆。界面同时显示实际在岗、目标、上限、空岗和当地可用劳动力；空岗不产生实际产出，也不按满员计薪。

适量待业余量有利于新增施工、扩产和补缺；余量过低难以补员，长期过高可能形成就业压力。具体阈值、用工上限倍数和效率函数未定。旧“设计岗×2.5”、矿洞效率表及各建筑岗数仅为[数值候选](参考数值与事件.md)，不能据旧百分比自动增加整数供给格。

### 2.3 用工效率、升级与自动化

实际工作效果受人员、材料、状态和任务影响。用工收益可以递减、过度拥挤可以降低效果；劳动密集、半自动、知识密集和服务设施的具体曲线仍待统一验证。兵营的旧战力曲线不作为新军事公式。

建筑升级扩大额定加工规模；技术和自动化改善同等人手下的工作效果，两者分开。技术可平移效率曲线，但不自动裁员：只有玩家调整目标或明确授权按目标效率调整，才释放相应人手。扩建也可能增加管理压力，由玩家通过人员配置、培养、调任或改善流程应对，不触发自动放权。科技结构与工艺突破的后续研究见[待审设计](待审设计.md)。

## 3. 通用生产建筑、配方与整数供给

### 3.1 建筑和配方

采用少量通用生产建筑，随已掌握技术、配方和实际条件切换用途；同一建筑当前采用一个配方，不同实例可分别承担各加工阶段。服务设施按自身实际效果处理，不强行写成可入库商品。

每座生产建筑具有物料输入、用工和产出接口。输入通过玩家显式连线从上游或总统府公共仓储取得；产出送往已连接的下游或仓储，尚未交付者留在本楼有限暂存。建筑暂存不是公共库存，不允许同一份物料同时存在于两处。

原料、半成品和成品原则上均可交易，木板可以出售；建成产线或存在多余产能不等于授权自动卖货，贸易按[贸易与财政](贸易与财政.md)处理。

### 3.2 格、等级和规模

“格”表示每个标准生产周期预留的额定供应量，不是地图格、物料现货或工人数量。每条有效线配置正整数，至少 1 格；不分配小数格。标准周期的游戏时间长度另审，不能直接套用旧年产率或现实秒数。

| 等级 | 伐木场额定木材 | 木板厂满产木材需求 | 木板厂额定木板 |
|---|---:|---:|---:|
| 一级 | 1 | 2 | 1 |
| 二级 | 2 | 4 | 2 |
| 三级 | 4 | 8 | 4 |

相邻等级额定规模翻倍，配方比例及加工损耗不变。等级上限、用工、升级代价和工期另审。升级保留已有线与配额，新增格由玩家分配；下游新增原料缺口要显示，不自动扩展上游供应。升级也不保证实际满产。

额度按资源／输出口分别计算，木材格不能用于铁。未来多产物配方的共享额度与联动方式仍待审，不预设可独立生成多份额外产能。

### 3.3 玩家建立和修改供给线

玩家在产业页点击或按住来源，拖到兼容的目标输入口，再指定整数配额。连接数量由可分配格自然约束，不另设“一级只能接几家工厂”的固定数量上限。

有效配置同时满足：

- 来源、目标与物料类型有效、兼容；同源同资源分配总量不超过额定产能。
- 同一目标、同种输入的总配置不超过该配方满产需求。
- 跨聚落连线不能绕过真实调运的时间和运力。

二级伐木场有 2 格，可给一家木板厂 2 格，也可给两家各 1 格。没有空余格时不能挤占已有线，须先减少、删除或确认一组新的配置。0 格不构成有效连接；未分配格不自动入库，入库也要显式连接到仓储。

断开只影响未来供应，已收到、已投入或已产出的物料按真实位置保留，不远程退回。换配方保留原物料，相关不兼容线标记“配方变更，待调整”，不继续向新配方错误供料；具体批次中途换方、退料及取消方式仍待审。

## 4. 真实生产、整件交付与暂存

额定产能、玩家已分配配额、实际运行和实际交付分别记录。缺人、缺料、玩家暂停、建筑停用或下游拒收可以降低实际结果，不自动缩减配额、重分配余量、均分或改线。

木板配方为木材 2→木板 1。只有每周期 1 木材时，材料与进度跨周期累计，两个周期交付 1 件木板；不产生可使用的半块木板，也不每周期向下取整到零而丢掉进度。名义上配置 1 格木板给下游时，界面应说明实际预计整件间隔延长，不能承诺每周期稳定到货。中断会改变预计时间，无法估计时说明原因。

| 配置示例 | 实际含义 |
|---|---|
| 伐木场 2 格→一家木板厂 2 格 | 原料条件满足时按满规模推进 |
| 伐木场 2 格→两家木板厂各 1 格 | 两家各较慢累计，分别整件交付 |
| 伐木场→木板厂 1 格、仓储 1 格 | 按玩家配置供给与入库，不自动把入库份额改给工厂 |
| 较慢木板厂→下游名义 1 格 | 保留配额，实际整件到货间隔较长 |

多输入配方按实际比例推进，例如制造装备同时需要木板和加工金属；一个输入短缺形成瓶颈，其他输入只在有限暂存中接收。投入时机、批次粒度与暂存容量仍待审，不能无上限吸入某种原料。

材料从公共库存或上游交付后，只记在真实去向；投入加工后不能再作为可用库存出售。未完成批次不算成品。目标不能接收时，完成品留在来源建筑输出暂存；暂存满则暂停相应生产或接收，不删除、不自动出售，也不另找目的地。等待保留原配置，条件恢复后按原设置运行。

缺粮造成的生产与施工劳动效率损失作用于实际结果和进度，不改额定格、配额、配方、连线或玩家用工目标，也不把效率下降当成人员死亡。人口损失及供粮后恢复见[人口与聚落](人口与聚落.md)。

## 5. 仓储、运输与粮食竞争

公共仓储与管理入口归总统府体系，不新增独立仓库建筑；各聚落独立记账，全国总览不合并可用库存。仓储容量、扩容与其他聚落的承载形式仍待审，不要求每座聚落都另建总统府。

仓储既能接收入库线，也能作为工厂的原料来源。工厂从公共库存取料同样需要玩家显式供给线与整数配额；库存不是无限产能源。实际出库必须扣除当地可用量，不动成交锁货、在途或其他建筑暂存。多种物料及总调拨能力参数另审。

跨聚落调运由玩家下达单次命令或明确授权重复规则，受时间与运力限制；发运扣来源、在途单列、到达入目的地，同一份货物只计一次。聚落内部先采用抽象供给图，不要求每条线建立实体传送带或逐车寻路；这不使异地调运瞬时完成。

当前居民只消耗粮食，自动从本地公共可用库存实际扣除，不另建生活节点、分发建筑或生活保留量。**同一游戏时点实际同时发生时，按合法新出口成交锁货→居民本次消费→有效仓储供粮线的建立顺序执行**，不等待未来市场轮，不回放先前消费。未成交单不锁货；同粮只锁一次。仓储供粮线的建立顺序在存档、刷新和调额度后保留，不提供排序按钮。单条线余粮不足配额时部分交付还是整量等待仍待审；这里不预设。完整条件、缺粮后果和时序以[人口与聚落](人口与聚落.md)为准。

## 6. 战损与维修对产业的影响

普通建筑轻损仍可使用；重损停用，保留本体、配方、用工与供给设置。未彻底摧毁者可手动维修，逐建筑自动维修默认关闭；开启后受损触发一轮至完好。维修只耗当地公共可用材料，不占维修劳动力或增加维修金币／工资，不挪用锁货、在途、装备或工厂暂存。

手动与自动共用按请求／触发时间排序的任务表，只在当前可执行任务中按原序领取当次可推进材料。缺料或实际受攻击暂停、保留顺序和成果、不继续扣料且不阻塞其他可执行任务；恢复按原序续修。修到可用后在原设置及运行条件满足时恢复生产，原玩家暂停仍保留，可继续修至完好。详规与维修队列 UI 见[军事与占领](军事与占领.md)。

普通建筑彻底摧毁后本体移除、原地腾空、无废墟。自身暂存原料、已完成未运出成品全损；未完成批次与进度作废，不生成成品，已投入材料不退还也不重复扣。公共库存及已送达下游的货物保留；仍存在且满足运行条件的下游可用自己已收到的暂存继续生产。旧维修结束，旧线失效，不自动重建、改线、转配方或重新分配格，新楼不继承旧进度。工作人员只记录实际战斗死亡一次；幸存者解除本楼用工，不自动填其他厂，也不解除主管正式任命。在途遇目标被毁的处理仍待审。

总统府采用控制血条易手规则，本体、公共库存、管理入口与有效连线保留，不能套用普通楼摧毁损失；锁货等原标记也保留。当地军事控制不等于正式吞并。完整占领规则见[军事与占领](军事与占领.md)；住宅容量与住房缺口见[人口与聚落](人口与聚落.md)。

## 7. 产业页面与操作规格

### 7.1 页面布局

产业页以当前聚落供给图为主，支持全国／跨聚落总览，但不将全国物料变为一份可用库存。

| 区域 | 必须表达的内容 |
|---|---|
| 顶部 | 当前聚落、资源／建筑筛选、搜索、异常筛选、调运总览入口 |
| 中央图 | 建筑卡、明确输入输出口、方向箭头与物料线；平移、缩放、选择、定位 |
| 选中详情 | 配方、等级、实际与目标用工、满产需求、输入／输出暂存、额定产出、实际进度；选中线的来源、目标、资源、配额与实际交付 |
| 编辑区 | 整数加减、确认／取消；修改前后分配总量、剩余格、目标缺口与无效原因 |

卡片显示名称、等级、当前配方、主要运行原因及空余产能。连线常态标方向、资源与配额，选中后可看实际交付。筛选和隐藏只改变显示，不停用或删除配置。公共库存、建筑暂存、待发货和在途使用不同字段。

### 7.2 拖线和修改流程

1. 在当前聚落选择来源；有多输出口时先选物料口。可兼容目标高亮并显示剩余需求，来源无余量时说明原因。
2. 拖到目标输入，使用整数步进器设置至少 1 格，受来源空余格和目标剩余需求限制。
3. 预览来源额定／已分配／剩余、目标满产需求／配置／缺口、预计整件交付节奏；预览不占正式额度。
4. 确认时重新核对实时的来源、目标、配方和最终总配额。编辑期间条件变化要显示冲突；同批编辑按最终结果校验，不重复占格。
5. 确认后保存配置并持续执行，不要求玩家每周期点击发货。取消或退出只丢弃未确认预览，原设置保留。

页面打开不自动暂停游戏；是否暂停由全局时间控制。不得接受小数、负数、超额或不兼容连接。

### 7.3 运行状态与提示

| 状态 | 玩家需要看到的原因或操作 |
|---|---|
| 未分配／可连接／无余量 | 空余格、现有分配及可改动位置 |
| 不兼容 | 输入物料、配方或聚落条件不符 |
| 供给不足 | 满产需求、已配置、实际收到和预计整件间隔；不把配额等同实际供应 |
| 停工 | 玩家暂停、缺人、缺料等实际原因及原设置 |
| 堵塞 | 目标拒收或本楼输出暂存已满，完成品仍在真实位置 |
| 库存不足 | 当地公共可用量、当次需求和未满足原因；不暗定不足整线交付方式 |
| 配方变更，待调整 | 受影响输入、输出、旧物料与失效线 |
| 轻损／战损停用 | 可用状态、生产状态与维修入口分别显示 |
| 维修中／缺料等待／受袭暂停／等待脱战 | 维修进度、当前材料需求／可用／缺口、暂停原因；暂停维修不等于停产 |
| 已修至可用／已修复 | 建筑可用状态与仍然存在的缺人、缺料、原暂停分别呈现 |
| 建筑摧毁／连线失效 | 来源或目标已毁；分项物料损失、批次作废、真实伤亡与幸存脱岗，不自动改线 |

维修开关说明为“受损即修，修至完好”；任务表显示启动顺序、建筑位置、进度与原因。被毁前可查看已知暂存原料、未运出成品和未完批次及全损说明；毁后区分原料／成品损失与批次作废，避免重复扣料。完整维修、摧毁 UI 详见[军事与占领](军事与占领.md)。

仓储供粮线增加可查的建立顺序、配置量、实际交付与等待原因，不增排序按钮或保留量设置。住房与居民粮食状态在现有人口、库存详情中查看，详见[人口与聚落](人口与聚落.md)，不再在产业页另造住户或生活配送系统。

分辨率、控件尺寸、配色、字体、图标、连线视觉和最终 UI 框架在实施时确定；以上字段与交互是后续创建 UI 的依据。返回[主方案](../殖民扩张自动化文明模拟_初步开发与设计方案_v0.1.md)。
