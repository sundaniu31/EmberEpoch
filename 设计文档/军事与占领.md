## 1. 军队编成、任职与科技

平时保留常备军，战时由玩家决定追加动员的人数、来源与编入军团，战后由玩家决定保留或复员。兵营组织已有居民的征募、编组与固定装备领取，不创造人口。同一人员不能同时占用军事、生产或施工岗位；抽调在岗人员须由玩家决定或在其明确授权内执行，并显示来源与经营影响。

一个兵营可配置多个军团，一个军团采用一种兵种。不同军团按战场职责配合作战；普通装备材料或代际改良保留原兵种，产生明显不同作战职责的关键技术才解锁新兵种。铜矛换铁矛不必另建兵种，接战、远程火力、攻城只是职责示例，完整清单与相互作用另审。

每个正式军团必须有一名玩家任命的军团长，与军事主管分别任职，遵守一人一正式岗位；不默认主管兼任，也不允许同一人正式统领多个军团。将领沿用五项通用能力、经历、关系及人物成长，不另设行业能力条，不公开隐藏能力数值。具体军事作用、军团长缺位或阵亡后的接替方式另审。

军事科技沿用工艺突破、传播与实际条件体系，不建立可点击的传统科技树。初始科技决定开局可选兵种；解锁只开放选择，不生成兵员、装备或当地生产能力。各兵种的技术发现、本地掌握、普及和材料门槛分别确定，不默认所有兵种都用同一种门槛；未知外国技术不直接公开。

### 1.1 固定装备与真实库存

每种兵种采用相应技术标准下的固定装备需求。玩家选择兵种与目标人数，系统列出必要物资，不逐项自由搭配武器、防具或多套兼容配装。

- 目标编制、实际人数与当前可编成人数分别记录；实际编成同时受真实可征募人员和每项必需装备约束。
- 装备领取后从公共可用库存转为部队已装备状态，不能继续出售或被其他军团重复领取。进口装备实际抵达后才可使用，发放时不重复按市价扣金币。
- 新技术可以更新固定装备标准，既有军团保留旧装备；玩家批准换装后才领取真实新装备，不自动升级、补员或改编。
- 固定配比、装备损坏、战利品、补充地点、换装批次、旧装备回收及复员装备处置仍待审，不增设远征军前线补给线。

例如目标100人，但某项必需装备只够80人，显示“当前最多可编成80人”，由玩家减少目标或补齐装备；不能擅改目标或按100人计算战力。数字只是约束示例。

### 1.2 取消部队训练

征募、动员、补员与改编均不经过训练。不设置训练队列、等级、士兵熟练度、费用或训练出战门槛，也不以“准备度”等名称补回训练等待。将领成长继续保留。

征募办理、集合、异地人员与装备调动是否耗时，另行确定；取消训练不表示远方人员或装备可以瞬间到位。

## 2. 人数、休整、复员与经营记账

普通士兵按群体与必要战斗数据处理，不逐人建立完整关系、记忆和对话档案。不另建独立伤员池、治疗队列或逐人伤病系统。

| 变化 | 实际人数与占用 |
|---|---|
| 征募、动员 | 总人口不变，实际人员转为军事占用，不能同时在民用岗位工作 |
| 已确认阵亡 | 实际兵员、真实人口与军事占用各更新一次 |
| 幸存部队短期休整 | 保留人数，只恢复状态，不补回缺额 |
| 补员 | 玩家安排真实人员与固定装备，不经过训练 |
| 复员实际完成 | 幸存人员解除军事占用，按实际状态重新供民用安排，不增加总人口 |

100人阵亡10人，休整后仍是90人。撤回或溃散的存活者不能全部记为阵亡；俘虏、失踪等机制未定，不把同一人同时记作多个互斥结果。

休整期间可接受移动、停止和回营驻扎等现有命令；尚未恢复时再次进攻，提示已知影响，由玩家决定。休整条件、时长及系数另审，依游戏时间推进，重复结束交战不额外恢复。

回营与复员分开：回营后仍是军人，继续占人和支付报酬；不自动补满人数。复员不自动回填征募前的建筑、挤掉现有工人或使远方人员瞬间返乡；民用安排仍依玩家设置及既有补员授权。异地归返、复员时长与装备回收另审，反复征募复员不能复制人口或装备。

军费按[贸易与财政](贸易与财政.md)的人员报酬、设施维护、贸易采购、专项支付归集，不另扣一笔总额军费。同一人同段占用只结一次报酬。军人按现有人口归属计入同一份居民粮食需求，不因行军、交战或军费分类重复扣粮，也不自动取用途经或外国聚落库存；异地供粮细节另审。居民缺粮影响人口、增长及生产施工效率，不据此增加军团战斗惩罚。

例如总人口200、可劳动120，征募30人后总人口仍200，可供民用90；阵亡6人后总人口194、军人24、可供民用仍90；实际复员8名幸存者后军人16、可供民用98。此例忽略其他变化，不固定编制、比例或工期。

## 3. 同一场景与四项命令

战斗直接发生在现有国家或聚落场景中，攻击真实敌军与可攻击建筑，不创建独立战斗地图或经营对象副本。实际位置、伤亡、建筑变化保留在经营世界。战斗、行军、经营和人物共用全局游戏时钟，暂停与调速统一生效；切换观察场景和战后汇总不重复结算。

玩家直接指挥军团，单兵执行合法任务；将领不越权改变战略目标、另开战争或签订条约。操作只有以下四项，不新增巡逻、阵型、朝向、支援、撤退或占领按钮，不默认驻扎加成或边走边射击。

| 命令 | 执行规则 |
|---|---|
| 移动 | 向指定目的地真实寻路；挡路或直接威胁本队的敌军触发临时交战，结束后继续原目的地 |
| 攻击 | 接近指定敌军或可攻击建筑并作战；敌军退离时进入固定起点的有限追击 |
| 停止 | 取消旧移动、攻击或返回；原地自动攻击射程内合法敌人，不移动接敌、不追击 |
| 驻扎 | 到达指定位置或己方可用兵营后，围绕固定驻扎点有限接敌，结束后返回原点 |

### 3.1 普通移动与临时接敌

原移动目的地与临时敌军分别保存。只有挡路、正在攻击本队等与实际通行和任务有关的直接威胁触发临时交战，附近无关敌军不使军团改变任务。

开始临时接敌时记录本军团位置作为本次固定边界起点。敌军退离、不再威胁、威胁解除或超出边界后，结束本次接敌并继续原目的地；若道路仍不通，恢复原等待任务。转向、重接战、恢复行军或电脑重发同一任务不刷新边界，不立即因同一已结束目标重开追击。

这里恢复的是原移动任务，不套用指定攻击超限后“返回起点并停止”的收尾，也不把临时反击变成无限追杀。具体威胁判定与距离另审。

### 3.2 停止与驻扎

停止后没有可攻击敌人便保持原地，目标出射程即停止攻击；不为换攻击位置而移动，也不恢复被取消的旧任务。

驻扎点在到达后固定，接敌、换目标或攻击位置调整均服从以原点为中心的有限范围，不能追着敌人逐次外移。威胁解除、目标出范围或继续追赶将越界时，实际返回原驻扎点，抵达后恢复驻扎。活动范围另审。

### 3.3 指定攻击与固定追击起点

初次接近远处敌军与追赶退离目标分别处理，不把下令位置直接作为所有进攻的限制中心。首次因指定敌军退离而需要跟随时，固定本军团当时的位置作为本次追击起点；即使尚未接敌，也不能以一直“接近”为由无限跟随。

追击范围按军团离起点的距离判断，不按累计路程；绕障碍不额外消耗路程额度。同次追击的锚点不因逐帧更新、移动、转向、重新接战、换临时目标或电脑重复同任务而刷新。

| 情况 | 结果 |
|---|---|
| 指定目标合法且仍在允许追击范围内 | 继续接近、攻击该目标 |
| 继续追赶将越过边界 | 放弃该轮追击，真实返回固定追击起点 |
| 超限返回完成 | 结束旧攻击，转为停止，不立即再次追出 |
| 指定敌军被击败、失效或不再敌对 | 结束指定攻击，不悄然换追另一支军队 |
| 新玩家命令 | 替代旧任务及返回安排，按新命令执行 |

固定建筑不进入移动目标追击流程。总统府成为己方后结束原攻击，第三方易主则先核验敌对关系。追击距离另审。

### 3.4 所有返回都优先返回

点击己方兵营回营、驻扎接敌后归位、超限追击回起点、电脑实际撤回，都保留返回任务身份。途中不自动攻击、反击、追击或为接战停下；底层寻路及单兵行为不得套用普通移动反击。返回仍会受到真实攻击，不提供无敌、瞬移、安全脱战或额外撤退伤亡结算。

选中军团点击己方兵营后，沿实际路径抵达并驻扎；驻扎归位后仍驻扎；超限追击返回后停止。原固定点不随受袭漂移。玩家可用新四项命令替换返回，电脑也须由指挥层明确替换任务，不能由底层自动反击接管。返回途中敌人靠近不自动重开已结束的追击。

### 3.5 道路受阻、目标失效与命令替换

| 情况 | 保留及处理 |
|---|---|
| 目的地有效，但受建筑、地形等阻挡 | 在可达位置等待，保留命令、原终点、返回身份、固定边界与任务进展，按游戏时间定期重寻，路通后继续 |
| 普通移动等待时遇直接威胁 | 临时交战后恢复原移动或受阻等待，不丢失原目的地 |
| 返回等待时遭到攻击 | 保持返回等待，不套用停止命令的原地开火 |
| 目标兵营被毁、易主或不再可用 | 提示原目标与失效原因，等待重新指定，不自动转成停止开火；电脑指挥层可明确改派，不永远找旧引用或自动换营 |
| 收到新命令、目标失效或任务明确替换 | 清除旧等待、重寻与返回安排，迟到的旧路径结果不得重新接管 |

有效终点暂不可达时，不能经过有限总次数重寻便自动放弃，也不额外破坏建筑、传送、消失或释放军事占用。道路受阻和对象失效不能混同。

重寻按军团集中、错峰安排，暂停不推进等待；不逐兵逐帧重找同一路。记录和存档保留当前命令、主临时目标、原终点、固定点、追击结束状态、返回与等待身份。恢复存档不得刷新边界、恢复已取消任务或重做损失。间隔、预算、寻路与避让算法另审，技术方案见[技术与美术](技术与美术.md)。

## 4. 电脑军团的十状态指挥

电脑指挥层接收已经成立的合法战斗任务，不负责国家建设、宣战、人物任命、动员倾向或国家战略目标生成。玩家军团不自动获得电脑的改目标、支援或撤回权限。双方同种命令使用相同射程、移动、实际命中、兵员和占领规则。

每个电脑军团分别保存主任务目标与临时交战目标、协同分工及行动进展。临时挡路敌军或支援对象不能覆盖主目标；判断使用实际发现或收到的信息，不预设电脑知道所有隐藏兵力和玩家计划，战争迷雾与侦察细则另审。

| 状态 | 行为与转移 |
|---|---|
| 待命 | 无有效任务时保留位置或驻扎；得到合法目标后接近 |
| 接近主目标 | 寻可达路线，到攻击位置后攻击；遇直接威胁转临时交战 |
| 处理临时威胁 | 攻击本队能够应对的直接威胁或挡路敌军，解除、远离或失效后恢复主任务 |
| 攻击主目标 | 在有效位置持续攻击；目标移动则调整，出现直接威胁则处理 |
| 调整位置 | 处理射程、堵塞或失效攻击位置；有位置则继续攻击，无位置则重判 |
| 支援友军 | 能力和位置允许时临时支援同任务友军，条件失效或威胁结束后恢复原任务 |
| 恢复主任务 | 重新核验目标归属、合法性和路线；仍敌对则继续，变己方则完成 |
| 任务完成 | 结束原攻击，按分工驻扎或接收下一任务；驻扎服从固定点规则 |
| 受阻重判 | 区分有效目标道路受阻与对象失效，分别持续等待重寻或等待明确替换 |
| 实际撤回 | 无力继续时向可达安全位置或己方可用兵营真实返回，途中不自动攻击，受阻等待，损失按实际记录 |

状态按实际条件转移，不要求线性走完。优先处理能够应对的直接危险，其次是必须击退才能通行的敌军，之后恢复主目标；不能因附近任意敌军每帧换目标。已合法有效的交战保持连续，临时目标不再威胁即结束，不能恢复已经取消或超限放弃的同一轮追击。

多个军团可共享主目标，但按射程、位置、可达性和威胁分别行动。短射程寻找可达接敌位置，长射程寻找当前武器允许的有效位置，位置有效则持续作战。受威胁军团与适合支援者处理敌军，其他军团继续主任务；正处理自身紧急威胁的军团不再承担另一支援，避免互相救援循环。同一军团不能同时计入多项互斥任务，不新增总司令岗位、兵种清单或阵型加成。

单兵只执行军团许可范围内的跟随、接近、射程判断、攻击间隔和归队，不能自行越界、改变国家目标或替指定军团另找追击对象。每发弹丸独立飞行和碰撞；表现优化不改变真实攻击结果。指挥按事件和游戏时间集中错峰复核，不逐帧重发仍有效命令；攻击和命中不因较低指挥复核频率而漏算。

主目标成己方则结束攻击，第三方接管须重查敌对关系，不自动宣战。军团长失效、支援与撤回阈值等另审。组织参考 [OpenRA 小队状态](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Mods.Common/Traits/BotModules/Squads/States/GroundStates.cs)及[小队管理](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Mods.Common/Traits/BotModules/SquadManagerBotModule.cs)，不移植其额外命令、造兵方式、国家战略或默认参数。

## 5. 总统府控制条与反复占领

总统府血条表示控制能力。有效敌对攻击打空控制条时，最后一次有效击破攻击的所属方取得对应本地聚落的军事控制；随后恢复一定正控制值，支持新的攻击和再次夺回，恢复量另审。

“无人化”表示原控制失效，不等于真实人员全部死亡。总统府本体、管理与仓储入口、公共库存及有效连线保留，不需重建或临时仓储入口。连线另一端的普通建筑真被毁时仍失效，不因总统府保留而复活。

不要求清空守军、驻扎计时、逐栋攻占或第五个占领命令。只改变这处聚落的军事控制，不自动吞并国家、转移其他聚落或生成另一座总统府。正式政治归属、条约及其他聚落行政承载形式另审。

### 5.1 物资、居民与守军

- 当地公共物资全部原量保留，只转管理归属，不另复制一份战利品；调往别处仍需真实时间与运力。
- 全国国库、其他聚落库存、在途、冻结款项与部队已装备物资分别记录，不随本地控制一并转移或重复计入可用量。
- 已成交锁货保留订单与锁定标记，不自动继承合同、解锁或重卖；战时合同履行、解除和款项归属另审。
- 幸存居民保留原岗位，建筑、人手、原料等条件具备时可继续运行；人口仍在原聚落，不复制劳动力。具名人物的正式任命、态度、关系与承诺不自动转给占领方。
- 剩余守军保持原所属和指挥权，仍可作战及接受原四项命令，不自动归顺、清空或复员。回营目标须当前属己且可用；兵营管理转移与占领人口征募另审，不凭空补驻军或军团长。

### 5.2 同时命中与当前合法性

同时命中采用统一确定顺序，不以线程先后、帧率或重复提交决定归属；同一次归零只产生一次有效占领。统一更新控制方、公共库存管理权、恢复控制值，并重判相关任务。

同笔伤害只结算一次，其溢出不循环击破新控制条；新的合法敌对攻击仍可伤及恢复后的控制值。新控制方不再攻击已属己方的总统府，原目标成己方则任务完成，第三方先检查敌对、不自行宣战。

已发射弹丸不因换命令、返回或易主而删除，仍真实飞行、碰撞，在命中时复核当前归属和有效攻击条件；己方占领攻击不生效。友伤、贯穿、弹丸互撞及特殊弹道仍待审。建筑、控制状态、库存与真实人员分别保存，战报和读档不重复扣人口、移除建筑或转移物资。

## 6. 普通建筑战损与彻底摧毁

| 状态 | 运行与场地 |
|---|---|
| 轻度受损 | 仍可使用，不新增随耐久连续递减产能的机制 |
| 严重受损 | 停止对应生产或服务，保留建筑与原设置 |
| 彻底摧毁 | 建筑移除，原地腾空，无废墟；由玩家另行重建 |

总统府控制条不套普通建筑删除与维修。住宅可用容量按[人口与聚落](人口与聚落.md)统计，重损已停用容量被毁后不再扣一次；住宅损毁不额外判居民死亡、强迁或解除其在其他工厂的工作，不设临时安置。

### 6.1 本楼物料与加工批次

彻底摧毁只结算被毁建筑自身实际尚存的暂存原料及已完成未运出成品：全部损失，不转公共仓储。未完成加工批次和进度作废，不生成成品，已实际投入材料不退也不从原库存再扣。统计成品损失时，不再将制造它的投入材料算成新增损失。

公共库存及已经送达其他建筑的物料保留；仍存在且满足运行条件的下游可用有限暂存续产，耗尽后才因缺料停止。存在连线不等于已经交付，尚在毁建筑内的成品仍全损。在途遇目的建筑被毁的处理另审，不自动退回或消失。总统府公共库存按占领规则全留。

### 6.2 真实人员与旧任务

建筑被毁本身不额外判工作人员死亡，实际战斗死亡只记一次。幸存工作人员解除本建筑用工，按实际状态等待重新安排，不增加人口、不自动填别厂。建筑用工与行业主管正式任命分开，不因一栋工坊被毁而免去主管。

结束旧维修任务，相关节点与连线标为来源或目标已毁。系统不自动重建、改线、转移配方或重新分配产能；重建后由玩家重新安排，不继承旧加工批次、加工或维修进度。损失、脱岗与任务终止只结算一次，刷新记录和读档不重扣。

## 7. 普通建筑材料维修

维修只适用于仍存在的受损普通建筑。玩家查看材料后手动下令；自动维修默认关闭，按建筑开启，说明为“受损即修，修至完好”。手动一次不等于永久自动授权，自动维修不包含自动重建，不为总统府恢复控制值。

只耗建筑所在聚落公共可用材料，按游戏时间自动推进，不占劳动力、不新增维修岗位、工资、金币费或专项收费；普通新建仍临时占施工劳动力。既有维护和在岗报酬按[贸易与财政](贸易与财政.md)原规则处理，不能写成维修期间全部免费，也不按材料市价重复扣钱。

不取锁货、在途、已装备物品或工厂暂存，不改产业线、不自行调运或凭空借其他聚落材料。同份材料不能被建设、维修、贸易重复领取。具体材料、批次和速度另审，不强制一次付清全楼材料。

### 7.1 轮次、启动顺序与当前可执行任务

手动请求与自动触发共用任务表，以该轮请求或触发时间登记启动顺序，不以首次领料时刻排序。每栋同轮只保留一单，重复点击、重检、重复受损、暂停和恢复不建新单或刷新顺序。

对当前满足执行条件的任务，按本轮原序从各自聚落领取当次能够实际推进的材料。不设维修库存保留量，不预锁整栋未来用料，不新增建设、贸易与维修之间的全局优先级。

缺料或受袭任务暂停，不领料、不占未来材料，也不阻塞其他当前可执行维修；不同材料、不同聚落不被一个缺料任务全局堵住。恢复后保留原序，但须依据当时可用材料，不追回其他任务已耗物料。修至完好结束本轮，后续再次受损才按新启动时间建立新轮，旧队首不能永久优先。

### 7.2 受袭暂停与修复成果

依据本建筑实际受攻击记录暂停手动及自动维修，不因战争状态、附近有敌军或别处交战暂停全部维修。脱离攻击且材料等条件满足后继续；脱战判定和确认间隔另审，不固定新冷却。如使用确认间隔，依游戏时间推进，新攻击重新判断。

暂停期间不推进、不继续扣料；保留已完成成果、原序与自动授权，不回滚、不退已耗料，恢复不重扣同份材料。实际新攻击仍造成伤害，“保留成果”不是免疫。缺料和受袭同时存在时均须解除才恢复。

### 7.3 可用、生产与维修分别判断

修到可用即可按原配方、有效连线、用工与玩家设置恢复，不必先修至完好；材料允许时继续修。缺人、缺料等仍等待，原玩家暂停仍暂停，不自动补人、改线、切配方或改产能。

可用不等于完好，完好不等于满产，暂停维修也不直接等于暂停生产。轻损可一边运行一边修，重损仍停用；已修到可用却缺生产原料、已完好但玩家暂停，均分别说明。彻底摧毁结束旧修，不能靠续进度复活。易主后任务与授权处置另审。

## 8. 后续 UI 制作依据

以下为信息与交互要求，不是已制作界面，不指定框架、距离滑块或完整布局；只显示玩家实际已知内容。

### 8.1 军团与战后记录

| 内容 | 字段或状态 |
|---|---|
| 征募、编成与换装 | 人员来源及经营影响，兵种和科技条件、固定装备需求、目标与实际人数、当前可编成人数、缺人缺装、军团长；新标准与换装实物需求由玩家确认 |
| 四项操作 | 仅移动、攻击、停止、驻扎；点击己方兵营显示实际回营，不设撤退按钮或独立结果页；移除训练及替代准备度条目 |
| 命令与执行状态 | 区分命令和原地交战、初次接近、追击、驻扎接敌、途中交战、恢复行军、返回、受阻等待、目标失效；它们不是新命令 |
| 原点与目标 | 原目的地、指定攻击目标、临时目标、固定驻扎点或追击起点及范围；驻扎点不漂移，下令位置不冒充追击起点 |
| 返回与受阻 | 显示回营／回驻扎点／回追击起点及原因，说明不自动攻击；道路阻挡与兵营失效分开，等待不显示成停止或已抵达，不虚构替换兵营 |
| 命令替换 | 目标、路线、锚点、范围与原因切换到新任务，不显示已取消任务仍将恢复 |
| 休整与复员 | 人数缺额与休整分开，进攻前说明未恢复影响；实际释放劳动力阶段与待定装备处置分开，不显示立即回填旧厂 |
| 电脑状态 | 已知主目标、临时目标、接近／交战／支援／重判／恢复／撤回和分工，不展示未知兵力或国家战略 |
| 战后记录 | 命令、真实战果、实际阵亡与幸存人数、军团长表现及相关已知反应；人数与目标编制分开，不再结算伤亡 |

故事基于已有关系和所知信息，可与将领、幸存者及实际存在的阵亡者亲属交谈，不为所有普通士兵临时捏造完整亲属档案。具名范围和生命周期另审。

### 8.2 控制、维修与建筑损失

| 位置 | 必须表达的信息 |
|---|---|
| 总统府 | 控制血条、当前控制方、实际易主；建筑与仓储入口保留、库存管理权转移；不误报全国吞并、人员死亡或守军归顺 |
| 普通建筑可用状态 | 轻损可用、战损停用、恢复可用、完好；与实际生产／服务状态及原玩家暂停分别说明 |
| 维修操作 | 手动按钮、默认关闭的逐建筑自动开关和授权状态，说明“受损即修，修至完好”；不显示维修工人、额外金币、保留量或优先级滑块 |
| 维修材料 | 本次推进所需、当地公共可用量、缺口；锁货、在途、装备及暂存不可用。整楼预计需求若展示，明确不等于已锁定 |
| 维修任务列表 | 本轮启动顺序、建筑及位置、进度；尚未推进、维修中、缺料等待、受袭暂停、等待脱战、已修复和再次受损新轮；多个暂停原因均可查，不虚构固定脱战倒计时 |
| 修复与运行 | 暂停保留成果，已可用但仍维修、已完好但缺料或玩家暂停分别显示；若展示预计时间，恢复可用和完全修好分开，缺料时不伪装确定完工 |
| 毁前详情 | 本楼已知暂存原料、已完成未运出成品、未完成批次，以及彻底摧毁的全损／作废说明；与公共库存分开 |
| 毁后损失 | 分列实际原料、成品损失、批次作废；不再重复加算已耗投入，不虚增成品或金币市价罚款 |
| 人员结果 | 实际战斗死亡与幸存脱岗分开，主管任命不自动解除；住房容量变化与实际人口变化分开 |
| 节点与旧任务 | 来源／目标已毁、失效连线、仍存下游的真实暂存和运行原因；旧维修结束，空地重建后重新安排，无旧加工或维修进度、废墟拾取入口 |

所有列表和记录读取同一权威状态，打开 UI、回看战报或读档不刷新顺序、不重复扣料扣人或释放用工。在途处置及其他未审结果不提前显示为已执行。
