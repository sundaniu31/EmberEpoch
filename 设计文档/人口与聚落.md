# 人口与聚落

> 设计基准 v1.31 · 2026-10-23。本文集中记录已确认的时间、人口、库存、住房、居民粮食与用途竞争规则；具体参数和未定系统见[待审设计](待审设计.md)。UI 内容是制作说明，尚未实现。

## 1. 游戏时间与统计

时间连续推进，玩家可以暂停、调速。生产、居民消耗、施工、运输、人物活动、行军与战斗使用同一游戏时钟；暂停不推进这些过程，调速不改变同段游戏时间的产出、需求或工作量。不另开独立战场时钟。

季度、年度汇总实际记录及明确列出的定期结算，不重复发放产出、扣除消费或人口损失。打开面板、切换视图、刷新、读取存档不额外推进结算。不同子系统可以采用不同调度频率，但不得改变统一游戏时间的含义。

游戏年季长度、倍率和各系统间隔尚未统一；旧稿的现实秒数、按季产消数字均不能直接覆盖当前规则。

## 2. 人口与劳动力

人口由实际出生、死亡、迁入和迁出改变；农业产粮，不直接生成人口。出生人口需要成长，不能立即变成工人。粮食可以来自本地产出入库或实际到货，不以聚落有没有农场作为生育开关。

普通居民按聚落群体统计，不逐人建立完整人物档案。总人口包含儿童、老人、暂不能劳动者等；年龄、健康影响当前可用劳动力。可用劳动力再区分在岗、待业及实际施工、军事占用，不能把总人口或全部未就业人口视为可招工池。

同一人同一时段不能被生产、施工、军事重复占用，所有群体都有粮食需求。征募只改变占用，不增加总人口；真实死亡只扣一次，复员实际完成才释放军事占用。调人及补员服从玩家目标和授权，详见[产业与建设](产业与建设.md)、[军事与占领](军事与占领.md)。

建筑建成不自动满员；施工临时占人、完工释放，投产再按已确认目标补员。普通建筑被毁不额外判工作人员死亡；幸存者仅解除该建筑用工，不自动填入其他岗位。住房损失不解除居民在其他建筑的工作，行业主管正式任命与具体用工分开。

聚落控制易手不生成、删除居民或自动改变个人态度；居民原岗位在实际条件具备时保留，幸存守军仍归原方，不自动计入新方民用劳动力。具体控制与战损见[军事与占领](军事与占领.md)。

## 3. 本地公共库存与运输

各聚落独立记账，内部搬运先简化。公共仓储功能与入口合并到总统府体系，不另设独立仓库建筑；其他聚落行政载体名称另定，不要求全国每城都叫总统府，也不因此全国共享库存。

公共可用库存、已成交锁货待发、在途、建筑原料和成品暂存分别记录，同一份物料只出现一次。产业从公共仓储取料仍须玩家显式连线；居民粮食按第 5 节直接扣库，建设供料细节另审。

| 状态 | 实际记录 |
|---|---|
| 发运前 | 仍在出发地；已成交货物保留锁货状态，不可再消费或出售 |
| 实际发运 | 从出发地对应记录扣除，转为在途 |
| 运输途中 | 不属于任何聚落可立即投入消费或生产的库存 |
| 实际抵达 | 从在途移除，按对应交付流程计入目的地库存或接收处 |

玩家决定调运对象、数量，或明确授权重复运输。跨聚落调运需要游戏时间和真实运输能力；远方库存不直接满足本地缺口。道路、选址和运力应影响实际过程，载具、运输用工、损耗、截获、退运等细则待审。国内调运不自动产生贸易货款，国际交付与冻结款项见[贸易与财政](贸易与财政.md)。

总统府控制条归零后本体、公共库存及管理入口保留，库存原量由新控制方管理一次；不复制或同时记给双方，不自动转移其他聚落库存、在途货物或国库。成交锁货和订单标记保留，战时合同处置另审。公共仓储容量、升级、调拨上限和满仓处置未定，不预设无限容量。

例如甲地有100木材、乙地有10，甲向乙发20：发运后甲80、乙10、在途20；抵达后甲80、乙30、在途0。暂停不抵达，调速不增加同段游戏时间的运输能力。该例不是运输参数。

## 4. 住房容量

每个聚落汇总全体居民与可用住房容量，儿童老人也计入；不逐栋记录谁住哪里。其他聚落空房不能直接消除本地缺口，容量不是强制人口硬上限。

| 住宅状态 | 可用容量 |
|---|---|
| 正常或轻损可用 | 计入适用容量 |
| 严重受损停用、在建 | 不计入；受损原建筑与设置保留 |
| 维修达到可用状态 | 恢复计入，不必等完全修好 |
| 彻底被毁移除 | 不提供容量；若重损时已扣，不再次扣 |

容量按实际状态变化更新一次。新建或修好只改善居住条件，不直接生成人口、回填阵亡人数。缺房主要限制后续人口增长，具体出生、迁入作用方式另定；不一律禁止出生迁入，不删除超出容量的居民、不额外判死、不强迁、不解除其他用工，粮食消耗继续。

玩家通过维修、新建改善容量，不加入临时安置、营地或完整无家可归事件链。维修只耗实际材料、不占维修劳动力；新建仍临时占施工人手，两者分别处理。

例如人口120、容量150，住宅损毁后容量110，缺口10，人口仍120；恢复容量不直接增加居民。

## 5. 居民粮食消耗

当前只消耗一种基础“粮食”，不另建名为口粮的商品。后续科技可解锁更多食品，生产、替代关系再审；解锁不自动增加必须同时满足的消费品，不新增营养、衣物、燃料、家具等生活需求。

全体居民按既有人口归属计一次需求，包括儿童、老人、待业和健康受限者。生产、施工、军事工作不叠加第二份居民消耗；军团移动、驻扎、回营或控制易手不再额外扣同一批人的粮，不会自动从沿途聚落或外国库存扣粮。本轮不另开行军耗粮、前线补给系统，异地供粮归属细则待审。

消费随游戏时间从本聚落公共可用库存自动扣除，无需玩家逐次确认，不设生活需求节点、分发建筑、居民连线或生活保留量。粮食产出仍按玩家连线流向，不自动改线、调用工厂暂存、挪用成交锁货或在途物资，也不自动从别城调入。贸易储备参考与原有锁货规则保留，不因无生活保留量而删除。

需求、实际扣粮和未满足需求分开：不足时只扣实际可用粮食，余下记缺口，不扣负库存或免费补足。例如需求100、可用于该次消费60，实际消耗60、未满足40。示例不确定消费周期、人均用量或人口损失比例。

## 6. 缺粮影响与恢复

根据实际未满足需求及经过的游戏时间，产生额外迁出、死亡，抑制人口增长并降低生产和施工劳动效率。短期缺粮即可产生人口损失，不以长期严重饥荒作为死亡起点；缺口越大、持续越久，影响越重，具体公式、比例、时长与边界待审。

不能仅因瞬时库存为零或检查一次就固定删人。效率损失与真实减员分别表达；效率只影响实际运行结果和进度，不自动改用工目标、配方、额定产能格、整数配额、任命或连线，也不扩展成军团攻击力、命中惩罚。

迁出和死亡分别记录，同一批人口不能因迁出、缺粮、自然或战斗死亡重复从本地扣除，总减少量不超过实际对应人口。后续粮需按剩余实际人口更新，已消费粮食不因随后减员退库。可用劳动力须与实际人口构成及占用一致；具体流失群体和用工释放细则待审，不自动补岗。

本轮只记录从本聚落迁出的数量和原因；迁出不算死亡，也不直接给别城加人。去向、接收和跨国跨聚落迁入待审，不新增逐人迁移路径模拟。具名人物完整生命周期仍待审，不自动扩成逐人饥饿系统。

后续实际需求持续得到满足，额外人口流失影响、增长抑制和效率损失逐步缓解；库存刚转正、单批到货或仍在途不等于持续满足，不瞬间清零。恢复期间再缺粮可以继续恶化，存读档不重置过程。已经离开或死亡的人口不自动补回，新增人口依实际出生迁入与住房等条件记录；恢复也不取消正常自然人口变化。

## 7. 粮食同一时点的用途顺序

本节为本轮新确认规则，仅排列同一游戏时点实际发生的粮食用途，不将日常消费延后等待市场，也不倒放或重排先前已发生的消费、成交与交付。

| 顺序 | 处理 |
|---|---|
| 1 新出口成交锁货 | 按现有贸易许可、价格、储备参考、真实可售量等限制复核，合法成交后锁定；同份粮食不得被多个订单重复锁定 |
| 2 居民本次消费 | 从锁货后的本地公共可用余粮满足本次需求；不足记实际缺口，按第 6 节产生影响 |
| 3 仓储向加工厂供粮 | 在剩余公共可用粮中，对有效且可接收的仓储供粮线按实际建立先后处理，保留各线整数配置 |

未成交卖单本身不锁货；“出口先”不放宽已有成交条件，也不取消贸易储备参考。新的合法锁货可能减少本次居民可用粮，不能因随后缺粮自动撤单、抢回锁货、提前使用在途或追回工厂已收到的物料。

这里只处理公共仓储同资源、同刻取粮竞争；直接供给且已交付工厂的粮不参与回收。连线建立顺序保存到存档，刷新、重进页面、改供给量或读取存档不重排；不增加排序按钮、自动均分或生活保留量，不更改玩家额度和供给方向。

余粮不足一条线的完整配置量时，是先交付已有整数数量，还是等待凑齐，尚待下一步确认；本节不预设部分交付、整量等待或自动欠量追发规则。

## 8. 后续 UI 制作说明

在现有面板补充以下内容，不新增生活大面板、分发页、逐人住址、饥饿营养条或配给滑块。

| 位置 | 信息与交互 |
|---|---|
| 时间与报表 | 暂停/倍率、明确游戏时段；报表汇总实际变化，查看不推进模拟 |
| 人口总览 | 当地总人口、年龄健康等已确认构成、可劳动/在岗/待业及施工军事占用；显示劳动力不足原因 |
| 住房 | 人口、可用容量、富余或缺口及来源；提示“住房不足，后续人口增长受限”，容量损失和人口变化分记 |
| 住宅详情 | 适用容量、是否可用和是否计入、维修入口；在建、重损待修、修到可用分开显示，无逐栋住户表 |
| 粮食详情 | 当前公共可用、锁货待发、在途、建筑暂存；本时段需求、实耗、未满足量和缺口程度，库存与流量不混为一数 |
| 缺粮与劳动 | 短缺已持续游戏时间、增长及生产施工效率影响；效率变化不显示为人数已减少，未批系数不伪造确定值 |
| 人口记录 | 实际迁出、死亡分别列数量、时间、原因，不把缺粮数量当死亡人数，不重复汇总战斗伤亡 |
| 恢复 | 持续满足后显示“恢复中”，说明暂时影响逐步缓解；复缺更新实际状态，不展示自动返还人口 |
| 库存与运输 | 聚落可用、待发、在途、容量分别显示；全国总量不能掩盖某聚落缺口，不能一键花用外地未达库存 |
| 出口成交预览 | 当前已知条件下的预计锁货量、锁后可用量和本次居民可能缺口，标明为预计值；确认时复核，成交和扣粮后读取实际记录 |
| 仓储供粮线详情 | 标明“新出口锁货→居民→加工”的同刻规则，显示连线建立顺序、整数配置、实际交付和等待原因；不提供排序按钮 |

库存、人口、产业、贸易界面共用同一实际记录。只显示玩家已知范围，预览和查看不锁货、扣粮、减人或改变连线。产业拖线交互见[产业与建设](产业与建设.md)，完整交易界面见[贸易与财政](贸易与财政.md)。
