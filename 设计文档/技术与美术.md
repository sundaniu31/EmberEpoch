## 2. CPU 多核与真实战斗计算

面向电脑，兼顾新旧配置；简单像素精灵帧动画支持数百至数千普通战斗兵员的规模需求。最低硬件、帧率和人数上限未定，不保证所有旧电脑达到同一规模。

### 2.1 轻量数据与集中调度

兵员和弹丸保存稳定标识、位置、所属、必要状态与行动数据，批量推进，不默认每个对象运行独立完整 MonoBehaviour.Update，更不为普通士兵附加完整人物关系和模型思考循环。

复用对象、数据与命中缓冲，按需预加载资源，降低临时分配、垃圾回收和瞬间尖峰；非紧急查询与表现工作错峰。具体频率与预算待测，错峰不能漏掉真实弹丸、改变已生效命令或重复结算。

### 2.2 Jobs／Burst 与统一回写

适合并行的线程安全数据计算包括空间索引构建、部分邻近候选筛选、移动和弹丸轨迹数学。每项任务明确读写缓冲及依赖，不并发争写同一世界对象，不把全部战斗或任意 C# 函数直接标成并行。

依赖完成后，由权威模拟统一验证和应用命中、阵亡、人口、建筑损伤与移除，生产链和表现随后读取。同次伤亡或摧毁只结算一次，战报不重扣人口或物料。

GameObject、UI、实例化及普通 Physics2D API 不能任意进入工作线程。必要引擎查询留在其允许的主线程路径；可并行几何检测需另用线程安全数据实现并验证，不宣称当前版本已有可直接套用的 2D 批量 Job 碰撞接口。基础能力见[团结 Jobs 手册](https://docs.unity.cn/cn/tuanjiemanual/1.0/Manual/JobSystem.html)与[Burst 1.8 文档](https://docs.unity3d.com/Packages/com.unity.burst@1.8/manual/index.html)，文档能力不等于本工程已启用。

### 2.3 寻路、接敌与失效任务

军团共享主路线，单兵处理附近移动与接战；空间划分查询邻近候选，避免兵员与弹丸全场两两遍历。建筑摧毁后的通行变化反馈路径数据，具体结构、算法、更新批次与避让方式后续验证。

指挥与重寻按军团集中、错峰安排，不逐兵逐帧重找同一路。事件触发加游戏时间复核；未变的有效命令不每帧重发。新命令或目标失效后，旧异步路径结果不能重新接管。固定追击锚点、所有返回不自动攻击等玩法边界以[军事与占领](军事与占领.md)为准，优化不能刷新范围、重开任务或漏算损失。

### 2.4 每发弹丸独立飞行、连续路径检测

每发弹丸保留独立轨迹与命中状态，实际飞行并碰撞，不以射击动画、伤害数字或一次军团命中率抽签代替。一次模拟步检测经过的路径，不只比步末位置；移动目标保存步内运动信息，空间候选范围覆盖相关运动，以处理两次采样间的交叉。

候选命中按统一权威规则确认，防止高速穿透、重复伤害或再次命中已移除对象。具体几何、步长和密集情况下的精度待测，不承诺绝无漏判。命中时核验当前所属与敌对条件，控制易主、停止或换命令不删除已发弹丸；具体占领结算见军事文件。

友伤、贯穿、弹丸互撞与特殊弹道仍待审，独立飞行不等于必须检测弹丸互撞。首期使用当前引擎兼容的 CPU 权威碰撞路径，GPU 模拟或碰撞只作瓶颈实测后另审候选。

## 3. GPU 批量显示与设备兼容

集中管理精灵帧动画，以共享图集、材质和当前版本兼容的批量绘制路径呈现兵员与弹丸。可评估自定义四边形实例化，具体 API、着色器与实际效果留待工程验证。

- 保留透明像素、Y 轴前后遮挡及实际需要的 2D 灯光、遮罩；按排序、材质和效果条件分批，不承诺全场一次绘制。
- SRP Batcher 已启用不代表精灵实例化完成；GPU Resident Drawer 统计字段不证明现有 SpriteRenderer 已受支持。
- Unity 全球版本6.5新增的 `RenderSprite`／`RenderSpriteInstanced` 不作为团结1.8.1工程依赖，不为采用新接口擅自升级。参考[2022.3 GPU Instancing](https://docs.unity3d.com/2022.3/Documentation/Manual/GPUInstancing.html)及[Unity 6.5 新增说明](https://docs.unity.com/en-us/engine/6000.5/manual/whats-new/unity65)。
- 保留 CPU 兼容路径并检测设备能力。未来评估 Compute Shader 时另验支持范围、状态一致性与回读延迟；批量安排 CPU／GPU 传输，避免每帧互相等待。
- 异步回读有延迟，不是即时无成本返回，不得造成伤害失序或重复。GPU 弹丸碰撞不列首期必做，也不未经批准改成唯一伤害依据。参考[Compute Shader](https://docs.unity3d.com/2022.3/Documentation/Manual/class-ComputeShader.html)及[AsyncGPUReadback](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Rendering.AsyncGPUReadback.html)。

表现分档可减少非必要粒子、光照、阴影，复用命中特效与音效；离屏可减少绘制。低档不删除真实兵员、弹丸，不少算碰撞，不改伤害、人口、建筑、命令或游戏时间规则，实际模拟继续。

## 4. 人物运行与 AI 接口

约100名完整互动人物包含外国人物，是规模设计目标，不是硬上限、全体居民覆盖承诺或性能实测。普通居民聚合，普通士兵轻量；同一具名人物只有一份权威记录，显示对象和模拟记录分离，不因后台或画面变化复制身份。人物各类状态的运行、调度与持久化规则统一见[人物与社会](人物与社会.md)第十一节。

AI 自由交谈和无 AI 台词选项读取同一状态、合法动作和人物可知内容，未知秘密不提供给人物自由使用。生成语言不能直接写模拟状态。涉及任命、拨款、派遣等实际动作，展示事项、对象、已知代价与条件，经玩家确认后由模拟层复核权限和最新条件，执行一次并记日志；校验失败与重复请求不重复改状态。

规则核心、对话表达与场景显示通过数据适配接口交换已知状态和合法动作。后台人物行为由规则推进，不为每人维持持续模型请求；异步对话或批量计算的结果须在权威状态提交时复核关联对象、任务和最新条件，场景对象及其他主线程接口由主线程回写。人物自主行为的权限仍见[人物与社会](人物与社会.md)，不将全部自主行为卡在玩家事前确认上。

人物、消息、任务与日志采用稳定标识及保存读取规则，不每帧扫描全部历史文本。先实现权威规则、日志和存档状态，再接入两种对话呈现；具体存储格式、频率、容量和调用接口另审，不把定点数、全量快照加增量日志、回放等旧候选当作既定实现。

## 5. 验证与开发阶段约束

当前继续整体设计，不启动模型、Demo 改造、实际游戏 UI、包升级或战斗性能验证。后续实现从独立纯 C# 核心、统一时间、标识、日志和存档开始，再按系统依赖接入场景、对话和显示，不因写完状态机就宣称游戏已经实现。已有 Demo 的能力以实际代码与说明为准。

整体设计完成后，以500／1000／3000名参战兵员作为递增测试档示例，并记录实际同屏数与弹丸峰值。覆盖密集接战、射击、拥堵通道、建筑摧毁、经营与完整人物并行、时间加速、长期存档及调查并发、新旧电脑；测量 CPU、GPU、帧时波动、内存、垃圾回收和命令响应，并核对人员、伤亡与建筑结果一致。

测试人数不是编制、同屏上限或最低配置保证，未测 FPS 不填作结论。旧“5万人、300聚落、2000建筑、单核4ms”不作为已批准性能红线；实现期结合目标设备和玩法重新定基准，不以性能降档偷偷删真实兵员或弹丸。

首期范围与后续里程碑以[主方案](../殖民扩张自动化文明模拟_初步开发与设计方案_v0.1.md)为准；旧人力、月数、百分比资源安排只是估算，不成为本轮排期。优先验证玩法与可读性，再扩美术量；单帧角色程序动画、特定商业插件、多人与 Mod 接口等旧技术候选见[待审设计](待审设计.md)，不当当前依赖。

## 6. 像素风格与模块化目标

采用现代2D像素风：精灵保留明确像素结构，光照、自发光、昼夜、火焰、水面可使用实时 Shader 表现，具体效果逐项验证，不以效果列表宣称已经实现。模块化部件与共享调色板复用素材，约70个基础部件拼接多种建筑为制作规划，不等于现有完整资产库。

本地参考图 `ChatGPT 图像 2026年10月22日 17_09_32.png` 用于清晰轮廓、统一光源、适量细节与物体比例；科幻外壳不沿用，当前为木材主导的早期聚落。调色板替换可辅助木、石、砖、混凝土、钢构等材质演进，不把换色当作新增结构细节。完整太空视图和无缝升空转场另审。

### 6.1 密度、逻辑占地与尺寸

尺寸为导出素材原始像素，不等于屏幕像素、不绑定现实米数。逻辑格保持1×1 Unity单位，新世界素材每格32×32像素、PPU=32；2048×2048逻辑地图、整数格坐标、建筑占地和存档位置不变。

成年居民及普通士兵新制作目标32×48画布、脚底定位，宽1格、高1.5格；现有16×24人物可过渡，整数放大不算新增细节，不要求本轮环境更新重画整套人物动画。既有16像素水陆、道路、山地表保留16 PPU，覆盖同一格；一个旧源像素对应2×2新基准像素，不把新精灵按旧 PPU 导入导致世界尺寸翻倍。

建筑地基像素宽高为整数占地格数乘32，画布另含立面、屋顶和少量透明余量。画布、透明区和不透明轮廓不代替逻辑占地检测。

### 6.2 视角、Pivot 与遮挡

建筑、树木、石块和人物统一俯视偏正面，主要立面朝南，左上受光，右下低对比接地阴影，不混用侧面或等距视角。

建筑占地西南角为整数格锚点，渲染位置为地基南沿中心；南沿在画布底部时 Pivot=(0.5,0)，底部透明余量为p时 Pivot=(0.5,p/画布高度)，清单记录。树按树干接地点、人物按脚底、矿石石块按接地中心排序；真实接地点不在图片底部中心时单独记录，不能按屋顶或树冠中心排序。

树冠和屋檐可跨格，通行和建造仍读逻辑数据；靠南的前景遮挡靠北对象，不由图集顺序反向遮挡。新素材脚底／地基按1/32 Unity单位量化。

道路宽度不随素材分辨率变化：林间小径1格，村庄道路2格，城镇主路3—4格，城市大道6格，狭窄木桥1—2格，主要石桥与城门通道3—4格；各格乘32得新原始像素目标，既有道路可用16 PPU背景。

### 6.3 色彩与细节

- 建筑以木墙、木梁、木瓦和木板门窗为主，石头集中于低基、炉灶或矿洞，不统一石墙红瓦，不保留参考图白色科幻外壳。
- 木材使用棕褐、蜂蜜与少量灰褐，树冠使用低饱和绿、蓝绿、少量黄绿；轮廓用深棕、深绿、深蓝灰，避免密集纯黑描边。
- 正式建筑建议不超过48个不透明颜色，单张树、矿、草、石建议不超过32色，透明不计；共享关键材质色。离线调色不等于运行时树叶色偏，后者另验。
- 以完整色面、2—4像素结构边与少量1像素收口表达体积，木纹叶片石纹按簇组织，避免逐像素噪点、抗锯齿灰边、柔焦、模糊渐变和写实细纹。
- 接地阴影小面积、分级硬边、低对比深绿灰或棕灰，不烘焙一圈纯黑或大片固定地面进透明精灵。
- 树木区分阔叶、针叶、大小和冠形，优先原生变体；不任意连续拉伸，镜像不能破坏光源。
- 草石疏密成组并大面积留白，路、门口、建筑占地与岸线过渡留空，避免远景变黑点。装饰不改变唯一地形属性，不凭外观新增资源。

| 大城市、首都 | 256×256 | 8192×8192像素 |
| 整颗星球地面 | 2048×2048 | 65536×65536像素 |

这是逻辑格数乘素材密度的算术范围，星球宽度仍约16座中城并排，不制作65536²整图贴图、不将地图格数扩大四倍。旧16像素地表理论范围32768²；使用视野区块及概要纹理管理。

近景相机采用32 PPU和整数像素倍数：1倍时一个新源像素对应一屏幕像素、一格32屏幕像素，2倍时一格64像素。同分辨率同缩放档的可见格数约为旧16 PPU时一半、面积约四分之一；旧存档缩放整数可保留，不保证同档取景完全一致。

各层是同一逻辑世界的显示，不复制人口、资源和建筑。完整太空层、云层升空、无缝无加载保证及其具体视觉实现见[待审设计](待审设计.md)，不由本轮分层显示自动批准。

### 7.1 导入与素材交付

- 新世界精灵：PNG/RGBA、Sprite、PPU=32、Point、关闭 Mipmap、Compression=None，常规 Scale=(1,1,1)；兼容地表保留16 PPU，纯UI图另按UI规则，不批改全项目 PPU。
- 保留原始生成图、精确导出PNG及画布、地基、Pivot、入口、资源分类清单。生成图需检查尺寸和透明；格式正确不代表原生像素结构、光源和美观通过。
- 以原生、整数2倍／3倍、实际近景及常用中景验收，检查门高与人物比例、占地提示、树木遮挡、草石远景黑点、锯齿、边缘透明残留与地面色调。
- 同覆盖面积RGBA像素内存约为旧16 PPU的四倍，不等于角色逻辑计算四倍；用有限变体、共享材质图集、视野区块和远景隐藏，不为环境装饰逐格建立 GameObject、Collider、Update。
- 远景先淡出或隐藏草碎石，树矿再转概要表达；整图读地理概要，不为细节绘制全星球树木。Atlas内存按实际尺寸、格式与动画数估算，不承诺高清素材固定十分之一体积或万级同屏。
